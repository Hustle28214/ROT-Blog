## DeFi 安全

我们在前面几节里讨论了共识、合约、密钥,现在把镜头对准这些底层积木在真实世界里搭出来的东西:去中心化金融,DeFi。

先给一个直观的数字。从 2020 年 DeFi 之夏至今,行业内因为漏洞和攻击损失的资金累计已经超过百亿美元,平均下来每周都有几百万到几千万美元蒸发。为什么会这样?一方面是因为合约把金融逻辑直接暴露在了对抗环境里,任何人都可以读源码找 bug;另一方面是因为链上的动作一旦发生几乎不可撤销,追责在实际操作层面几乎不可能。这就相当于把一家银行的金库设计图开源出来,然后告诉全世界:找到漏洞的第一个人可以合法搬空它。

这一节我们把 DeFi 里最重要的几类攻击面串一遍。目标不是穷举所有已知漏洞,而是建立一种"看到这个模式就该警觉"的直觉。

### 闪电贷

闪电贷是 DeFi 独有的原语,先讲清它的机制,再讨论它带来的问题。

它的核心特性是:允许我们在同一笔交易里借出、使用、归还任意大额资金,不需要抵押。听起来像是免费的午餐,为什么可以做到?答案是原子性——EVM 允许一笔交易在结束时"整体回滚"。所以贷方可以放心大胆地借出任意金额,只要在同一笔交易结束前没有还上,整笔交易连带借款一起被回滚,等于什么都没发生。

一个正常用途的伪代码大致长这样:

```solidity
function executeFlashLoan(uint256 amount) external {
    aave.flashLoan(address(this), USDC, amount);
}

function executeOperation(uint256 amount, uint256 fee) external {
    // 拿到 amount 之后可以做的事:套利、清算、抵押品置换……
    IERC20(USDC).approve(address(aave), amount + fee);
}
```

闪电贷本身不是漏洞,它是一个中性工具。用它可以做套利,可以做清算,可以做抵押品置换,这些都是有益的市场行为。问题在于,它把"没有资金的人"和"能瞬间调用千万美元流动性的人"之间的距离归零了。历史上凡是合约里隐含了"攻击者不可能有那么多钱"这一假设的地方,几乎全部被闪电贷证伪。

理解这一点之后,后面几种攻击很多都跟闪电贷有关——不是闪电贷造成了漏洞,而是闪电贷把原本"经济上不可行"的攻击变成了"几十美元手续费就能做"的攻击。

### 预言机操纵

我们从一个具体的合约漏洞讲起。假设一个借贷协议要接受 ETH 作为抵押品,借出稳定币。它必须知道"当前 1 个 ETH 值多少美元",于是聪明的开发者写下了这样一段代码:

```solidity
function getEthPrice() public view returns (uint256) {
    (uint112 r0, uint112 r1, ) = uniV2Pool.getReserves();
    return r1 * 1e18 / r0;
}
```

这段代码从某个 Uniswap V2 池子里读当前储备量,算出瞬时价格。它看起来干净、无第三方依赖、完全去中心化,似乎是理想方案。但它有一个致命问题:池子的价格是可以被任何一个能借得起闪电贷的人操纵的。

攻击流程几乎已经模板化:第一步,闪电贷借 1 亿 USDC;第二步,把这 1 亿 USDC 全部塞进 Uniswap 池子换 ETH,池子的储备关系被打破,瞬时价格被拉高很多倍;第三步,调用受害合约的借贷函数,用 1 个 ETH 作抵押"合法地"借出被吹起来的价值对应的资产;第四步,反向操作把池子价格恢复;第五步,还闪电贷,把利润揣走。

历史上 bZx(2020)、Harvest(2020,损失 2400 万)、Cream(2021,损失 1.3 亿)都是死在这个模式上。攻击者甚至不需要理解合约的业务逻辑,只需要认得出这段"读现价"的代码就可以下手。

那么正确的取价方式是什么?两条路。

第一条是时间加权平均价(TWAP)。不是读当前一个瞬间的价格,而是读一段时间窗口内的平均价格。想操纵一个 30 分钟窗口内的平均价,攻击者需要在整个窗口内持续维持被操纵的状态,成本高得多。Uniswap V3 内置了 TWAP oracle,一行代码就能读到:

```solidity
(int24 tick, ) = OracleLibrary.consult(pool, twapInterval);
uint256 price = OracleLibrary.getQuoteAtTick(tick, 1e18, WETH, USDC);
```

第二条是用去中心化的价格聚合器,最主流的是 Chainlink。若干个链下节点分别去多个交易所抓价,聚合成一个中位数,签名后写到链上。DeFi 蓝筹几乎全部用 Chainlink。用的时候记得校验时间戳,防止读到几小时前的过期价:

```solidity
(, int256 answer, , uint256 updatedAt, ) = feed.latestRoundData();
require(answer > 0 && block.timestamp - updatedAt < 3600, "stale price");
```

### MEV:出块者的隐形税

MEV 是 Maximal Extractable Value 的缩写,指出块者通过对交易的排序、插入、审查所能获取的额外收益。它是 DeFi 生态里一个不太光鲜但每天都在发生的现象。

具体形式有几种。最常见的是三明治攻击:你在 Uniswap 上要用 10 万 USDC 换 ETH,交易一广播到公开 mempool,搜索机器人立刻看到。它抢先在你之前买入一笔,把池子价格推高;等你的交易按被推高的价格执行完,它再反向卖出。你的滑点变成了它的利润。

抢跑(front-running)是三明治的简化版:看到你要买某个代币,机器人先我一步买入,再高价卖给你。反向清算则出现在借贷协议里:看到某个借款人要被清算,机器人抢先执行清算并领取奖励。

用户层面的防御方法有几种。首先是用 MEV 保护类 RPC,比如 Flashbots Protect、MEV Blocker,交易不进公开 mempool,而是直接送给出块者。其次是控制自己的滑点参数,不要让 UI 默认的 3% 滑点被机器人吃满。再就是大额单拆成小额,或者用 CoW Swap、UniswapX 这类批量拍卖协议——它们的核心思想是让多个订单在链下匹配,链上只结算一次,顺序上没有可抢跑的空间。

合约层面也可以设计得对抗 MEV。提交-揭示(Commit-Reveal)模式:先提交一个 hash,过一段时间再揭示内容,这样在你揭示之前没人知道你要做什么。批量拍卖:一批订单同时定价,顺序无关。这些都不是新东西,只是在链上世界里被重新发现。

### 跨链桥:最贵的攻击面

跨链桥是 DeFi 里被盗最严重的品类。原因不难理解——桥的两端在两条完全不同的链上,而两条链之间没有原生的方法互相验证对方的状态。于是桥必须自己维护一套"消息真实性"的信任模型:多签、乐观证明、zk 证明,或者别的什么。这套信任模型往往是整个系统里最脆弱的环节,而桥又锁着几十亿美元的资金,收益期望极高。攻击者们最理性的选择就是把火力对准桥。

历史上几起代表事件:Ronin 桥 2022 年被盗 6.25 亿美元,起因是 5/9 多签里的 5 把钥匙被社会工程学拿到——严格来说这甚至不算合约漏洞,而是钥匙管理失败。Wormhole 同年被盗 3.26 亿美元,原因是签名验证逻辑里的一个 bug,让攻击者能伪造 guardian 签名。Nomad 桥 2022 年被盗 1.9 亿美元,起因是初始化时把 Merkle Root 设置成了 0,导致任何人构造的"证明"都能通过验证——事发之后甚至演变成了"抄作业式"抢劫,几百个地址跟着一起薅羊毛。Poly Network 2021 年损失 6.11 亿美元,漏洞在跨链消息的权限校验上,攻击者直接调用了 keeper 换人函数。

从这些事件里我们能看到几条通用的建议。第一,消息校验必须有可验证的链源证明,而不是简单地信任几个多签地址。第二,即便要用多签,也不能是普通多签——至少要门限签名 + 硬件隔离,私钥不集中存放。第三,资金不要都堆在一个池子里,要设阈值,超过就自动暂停。第四,复杂性是敌人。桥的代码越复杂,漏洞越多。

### 可组合性风险

DeFi 有一个很好听的口号叫"金钱乐高"——协议之间可以任意拼接组合,一个协议的输出可以成为另一个协议的输入。这个特性带来了创新,但它也带来了一种全新的系统性风险:一个组合系统的安全性,等于它所有依赖项中最弱的那一环。

一个例子。协议 A 用协议 B 的 LP token 做抵押;协议 B 用协议 C 的稳定币做储备;协议 C 用协议 D 的价格作为预言机;而协议 D 的价格来源恰好又是协议 A 自己的池子。这样一个循环依赖 + 价格反馈的系统,只要任何一环被撬动,就可能引发连锁爆仓。2022 年 Mango Markets 被 Avraham Eisenberg 用 4000 万美元操纵 MNGO 价格,然后用被吹起来的 MNGO 作抵押借出 1.16 亿美元,就是这个模式的完美演绎。

写协议时的直觉应该是:每当我引入一个外部依赖,我就把它的所有风险都拉进了我的系统。选择依赖不能只看功能,还要看它的安全审计、社区规模、失败历史。

### 一些代码级别的常见漏洞

除了上面几种系统性攻击面,在合约代码层面还有一些反复出现的 bug 模式,值得单独说一说。

**未校验返回值**。有些老的 ERC-20 代币(比如 USDT)的 `transfer` 函数不返回 bool 值,而是失败时 revert 或者什么都不做。如果我们用普通的 `token.transfer(...)` 判断成功与否,可能会遗漏错误。规范做法是使用 OpenZeppelin 的 `SafeERC20.safeTransfer`,它做了兼容性包装。

**精度损失和舍入方向**。在很多借贷/vault 协议里我们会看到这样一段代码:

```solidity
uint256 shares = amount * totalShares / totalAssets;
```

初始状态 `totalAssets = 0` 会直接除零;更狡猾一点,攻击者可以第一个存 1 wei,然后直接向合约转一大笔,把 `totalAssets` 拉高,后续用户存款计算出的 shares 会被舍成 0——这就是所谓的"首存者攻击"。防御方法是初始化时铸造一定数量的 shares 到零地址,让攻击者无法通过极端小的存款操控比率。

**签名重放**。跨链场景下同一个签名可能被拿到另一条链上重放,同一条链上同一个操作可能被重放多次。防御方法是在签名数据里塞进 `chainId`、`contractAddress`、`nonce`,EIP-712 已经把这套做成标准。

**Owner 权限过大**。如果一个合约里有 `onlyOwner function withdrawAll()`,那 owner 一跑路合约就归零。这类合约在信任模型上和"把钱交给某个匿名开发者"没什么区别。稍微好一点的做法是 owner 换成多签;更好一点的是加上 Timelock,让重要操作必须先公示一段时间再执行;最理想的是干脆放弃 owner 权限(renounce)。

**未保护的初始化**。代理合约模式下,`initialize()` 函数如果没有加"只能初始化一次"的保护,就可能被抢先调用,让攻击者当上 owner。上线时必须把部署和初始化打包在同一笔交易里。

### 上线前后的做法

前面讨论的是"漏洞长什么样",现在我们讨论"如何减少漏洞进入生产环境的概率"。这是一个多层防御的问题,没有单点解决方案。

事前:审计不是单一环节,而是一套流程。行业内成熟的做法是至少找两家不同风格的审计公司,因为一家没查出的问题另一家可能查得出。对核心业务逻辑(AMM 曲线、清算逻辑),形式化验证工具比如 Certora、Halmos 能把不变量用逻辑表达式写出来,遍历所有可能路径。模糊测试工具比如 Echidna 和 Foundry 的 Invariant Testing 可以定义"永远为真"的性质,让工具自动构造反例。

事中:发布前先在测试网、灰度网络上跑一段时间,主网上线初期设置资金上限,让潜在漏洞的最大损失可控。

事后:挂长期漏洞赏金。Immunefi 是行业标准平台,严重漏洞的赏金能开到 1000 万美元。这个数字看起来惊人,但对协议方来说,一个赏金猎人拿走 1000 万,总比黑帽拿走 1 亿要划算得多。

监控:在链上部署 Circuit Breaker,检测到异常资金流出就自动暂停合约,人工介入。有些协议甚至有专门的"应急委员会",可以在数分钟内响应事件。

### 给使用者的一些经验

最后我们从用户视角说几句。

不熟悉的协议,先用小额资金试水,别把大额直接扔进去。协议存活的时间是一个非常有力的信号——一个跑了两年、经过多轮审计、有活跃赏金的老协议,和一个上线一周的新协议,风险不是一个量级。

第三方评估网站可以参考,DeFi Safety 会给协议打分,Rekt Leaderboard 记录了历史被盗事件——一个协议是否上过榜是一目了然的负面信号。

授权最小化,用完就 revoke。前面钱包安全那一节说过,`approve(uint256.max)` 是危险的懒惰。

关注协议的治理动态。管理员权限的悄悄变更、Timelock 被缩短、多签地址的移交——这些都是"跑路"(rug pull)的前兆。

高得离谱的收益率必然有对手方风险。稳定币"20% 年化"这种听起来太好的事,通常在几个月内就会以某种方式崩掉。Terra 就是这个模式最典型的教训。

### 小结

DeFi 是一个把金融逻辑写成开源代码的实验。它带来了前所未有的开放性,也把攻击面暴露在了永不休息的对抗环境里。这一节我们讨论的五类攻击面——闪电贷、预言机、MEV、跨链桥、可组合性——每一类都对应着数亿美元级别的历史损失,并且每一类都还在以新的形态出现。

从工程角度看,DeFi 的安全问题不是"某个 bug 修完就没事了",而是一个持续演化的博弈。防御方需要不断学习新的攻击模式,攻击方也在不断寻找新的组合漏洞。写协议的人和用协议的人,都需要保持一种"始终假设自己会犯错"的谦逊。
