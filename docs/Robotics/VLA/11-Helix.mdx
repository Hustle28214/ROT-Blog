# Helix：人形机器人的双系统 VLA

博客/论文：[Helix: A Vision-Language-Action Model for Generalist Humanoid Control](https://www.figure.ai/news/helix)（Figure AI，2025）。Helix 要解决的问题非常具体：**现有 VLA 方案为什么不能直接用在人形机器人上？** 35+ 自由度的动作空间对离散 token 表示是噩梦，VLM 的推断延迟（100–200ms）和 200 Hz 的控制频率之间有数量级的差距，全身协调（躯干移动会同时改变工作空间和视野）让单一控制器极不稳定。Helix 的解法是**双系统架构**：7B 参数的 VLM 负责慢速语义推理，80M 参数的轻量模型负责 200 Hz 实时控制，两者通过共享 latent 向量耦合。

## 1. 为什么人形机器人是 VLA 的特殊挑战

| 挑战 | 具体问题 |
|---|---|
| 超高 DoF | 35+ 自由度，离散 token 动作表示爆炸 |
| 控制频率 | 200 Hz，而 VLM 推断约 7–9 Hz，差距 20–30× |
| 全身协调 | 躯干/头部移动同时改变工作空间和视觉输入，反馈不稳定 |
| 数据稀缺 | 人形机器人遥操作数据远少于单臂 |

人形机器人不是"参数更多的机械臂"，而是在几乎每个约束上都更难的系统。

## 2. 双系统架构

**System 2（S2）—— 慢速思考：**

- 参数量：**7B**（基于开源 VLM，互联网预训练）
- 运行频率：**7–9 Hz**
- 输入：单目摄像头图像 + 机器人状态（腕部位姿、手指位置）+ 自然语言指令
- 输出：一个**连续 latent 向量**，编码高层语义意图

S2 负责场景理解、语言 grounding、语义规划——它不直接输出动作，只输出意图向量。

**System 1（S1）—— 快速执行：**

- 参数量：**80M**，交叉注意力 Encoder-Decoder Transformer
- 运行频率：**200 Hz**
- 视觉主干：全卷积多尺度，**完全在仿真中预训练**（解决真实数据稀缺问题）
- 输入：S2 的 latent 向量（投影后与自身视觉特征通过交叉注意力融合）
- 输出：**35 DoF 连续关节动作**

S1 不做语义推理，只管快速准确地把 S2 的意图转化为连续电机指令。

**系统耦合：**

S2 持续更新共享内存中的 latent 向量，S1 每个 200 Hz 控制 tick 读取最新值。训练时**梯度从 S1 反向传播回 S2**，通过 latent 向量实现端到端联合优化，即使两个系统运行频率差 20–30 倍。

训练时引入**时间偏移**（temporal offset），模拟真实部署中 S2 慢更新 + S1 快读取的时间差，消除训练推断分布偏移。

## 3. 动作空间设计

35 DoF 覆盖：
- 每个手指的**弯曲和外展**（精细灵巧手控制）
- 每条手臂的 **6-DoF 腕部位姿**
- **躯干朝向**
- **头部注视方向**
- 一个合成的**"任务完成百分比"标量动作**——使模型能够自主终止行为、序列化子任务，无需显式状态机

"任务完成百分比"这个设计很关键：它把"何时停止"这个决策编码进了动作空间，模型不需要外部的任务完成检测器。

## 4. 训练

- **~500 小时**遥操作示范数据（描述为"不到同类 VLA 数据集的 5%"）
- 多机器人、多操作员数据采集
- **自动语言标注**：用独立 VLM 对视频片段做事后语言指令生成，无需人工标注
- 单一训练阶段，**单一权重集**——无任务专用微调、无独立动作头
- 标准连续动作回归损失
- 训练物体全部从评估集中排除，测试泛化

S1 的视觉主干完全在仿真中预训练，解决了人形机器人真实视觉数据稀缺的问题。

## 5. 部署：全板载，无云端

每台 Figure 02 机器人运行**双嵌入式低功耗 GPU**：

- GPU 1：S2 异步后台进程（7–9 Hz VLM 推断）
- GPU 2：S1 硬实时进程（200 Hz 控制）
- 共享内存 latent 向量桥接两块 GPU

Helix 是首个宣称**完全在嵌入式低功耗 GPU 上运行、无云端依赖**的 VLA——对于需要在无网络或低延迟环境中部署的人形机器人是关键属性。

## 6. 关键能力展示

| 能力 | 结果 |
|---|---|
| 新物体泛化 | 通过自然语言提示处理数千件新家居物品 |
| 多机器人协同 | 两台 Figure 02 使用相同权重，通过语言角色分配零样本协作 |
| 数据效率 | 约 500 小时训练数据，比同类 VLA 少 20 倍 |
| 控制频率 | 200 Hz，与专用单任务模仿学习策略持平 |
| 零样本语义抓取 | 处理抽象命令（"拿沙漠的东西" → 仙人掌玩具）|

多机器人协同的设计值得单独说明：两台机器人共享同一套权重，任务分工完全靠自然语言角色分配（"你负责左侧，你负责右侧"），不需要显式的机器人间通信协议。这意味着扩展到更多台机器人不需要修改任何架构。

## 7. 与其他 VLA 的对比

| 维度 | Helix | π0/π0.5 | OpenVLA |
|---|---|---|---|
| 目标平台 | 人形（35+ DoF） | 双臂（14–19 DoF）| 各类单/双臂 |
| 控制频率 | **200 Hz** | 50 Hz | ~6 Hz |
| 动作表示 | 连续（无 token 化） | 流匹配 | 离散 token |
| 系统结构 | 双系统（7B + 80M）| 单模型 | 单模型 |
| 部署 | 全板载（无云）| 部分板载/云端 | 云端/本地 GPU |
| 数据量 | ~500 小时 | ~10,000 小时 | 97 万条 |

## 8. 局限

Helix 的定量评估没有公开——展示均为视频，无具体成功率数字。S1 仿真预训练视觉主干在极端光照或高度杂乱的真实场景中鲁棒性未知。500 小时数据上的泛化能力到任务复杂度增加时是否还能保持，缺乏系统评估。双系统 S1/S2 可以独立升级，但两者协同的稳定性如何随 S2 的 VLM 骨干替换而变化，论文没有消融。
