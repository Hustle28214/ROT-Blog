# 阴影映射原理与实现：从光源看世界，再回到相机

阴影是几何存在感的第一证据。没有阴影的场景像贴在天空盒上的贴图，物体与地面失去接触点，视觉上会"漂"起来。1978 年 Lance Williams 在 SIGGRAPH 上发表 *Casting Curved Shadows on Curved Surfaces*，提出了**阴影映射**（Shadow Mapping）——一种用图像空间深度比较来判定遮挡的算法。这个算法后来统治了实时图形四十年，直到光追硬件出现才有了替代品。它的核心洞察只有一句话：**从光源看得见的表面就是被照亮的，看不见的就是阴影**。

## 1. 算法总览：两遍渲染

Shadow Map 是典型的**两遍法**（two-pass）。

**第一遍**：把摄像机放到光源位置，用光源的视锥体作为投影矩阵，对场景做一次几何渲染。不写颜色缓冲，只写深度缓冲。渲染完得到一张**深度纹理** $D_L(u,v)$，记录了"从光源看每个方向上最近的表面深度"。

**第二遍**：切回摄像机视角正常渲染。对每个片段，把它的世界坐标 $P_w$ 变到光源空间：

$$
P_L = M_{\text{light\_proj}} \cdot M_{\text{light\_view}} \cdot P_w
$$

除以 $w$ 得到 NDC 坐标 $(x,y,z) \in [-1,1]^3$，映射到 $[0,1]^3$ 得到纹理坐标 $(u,v)$ 和参考深度 $z_{\text{ref}}$。采样阴影图 $D_L(u,v)$，比较：

$$
\text{visibility} = \begin{cases} 1 & z_{\text{ref}} \le D_L(u,v) + \varepsilon \\ 0 & \text{otherwise} \end{cases}
$$

前者在阴影外，后者在阴影内。$\varepsilon$ 是**偏移量**（bias），下面会详细讨论。

流程图：

```
 光源视角                            相机视角
 ┌──────┐   pass 1                  ┌──────┐   pass 2
 │场景  │  ─────────>  Depth Tex ─> │场景  │  ─── 采样 ──> 着色
 │几何  │  仅深度                    │几何  │  比较深度
 └──────┘                            └──────┘
```

优点是**图像空间**——阴影生成的开销与场景几何复杂度线性相关，与接收阴影的表面无关，可以处理任意曲面，可以硬件加速。缺点是**分辨率有限**——阴影图是一张固定分辨率的纹理，锯齿、失真、透视变形全从这里来。

## 2. 光源类型对应的投影

不同光源的阴影图生成方式不同。

**方向光**（阳光）：光线平行，用**正交投影**。视锥体退化成长方体。光源"位置"没有意义，只有方向；渲染时把光源放在一个能覆盖整个场景的距离。

**聚光灯**（Spot Light）：光线从一点发出且有角度锥。用**透视投影**，视角等于聚光锥角。一张 2D 深度图够用。

**点光源**（Point Light）：向所有方向发光。需要 **6 张阴影图** 拼成一个立方体（Omnidirectional Shadow Map），采样时用 3D 方向向量做立方体贴图查询。或者用双抛物面映射（Dual Paraboloid）压成两张 2D 图，代价是深度失真更严重。

| 光源 | 投影 | 阴影图数量 | 采样方式 |
|---|---|---|---|
| 方向光 | 正交 | 1（或多级 CSM） | 2D 纹理 |
| 聚光灯 | 透视 | 1 | 2D 纹理 |
| 点光源 | 透视 6 面 | 6（立方体） | Cubemap 方向查询 |

方向光的正交投影没有透视除法后的"近处密远处疏"问题，但整个视锥体的深度范围要覆盖整个场景，深度精度会被拉薄。这就是为什么方向光的阴影最麻烦——分辨率永远不够用，见 [CSM](#7-级联阴影-csm)。

## 3. 自阴影伪影：Shadow Acne

朴素实现会得到满屏的**斑马纹**，明明是平面却出现平行条纹。这就是 Shadow Acne。

**原因**：阴影图存的是**离散化**的深度。一个连续的平面在光源视角下被采样成 $N \times N$ 个深度值，每个 texel 只存了一个深度。当片段的实际深度和 texel 存的深度做比较时，同一个 texel 覆盖的连续表面上，有些片段深度比存的值大、有些小——大的被判为阴影，小的不被判为阴影。加上深度缓冲本身的量化误差（24 位深度也只有 $2^{24}$ 个可辨深度），条纹就出现了。

```
   实际表面   ─────────────
                ╱  ╱  ╱  ╱     ← 每个 texel 存的深度
              ╱  ╱  ╱  ╱       是一个"阶梯"
            ╱  ╱  ╱  ╱
       texel  texel  texel

   表面高于存的深度 → 判为阴影 → 黑条纹
   表面低于存的深度 → 判为亮   → 亮条纹
```

**朴素解法**：加常数偏移 $\varepsilon$：

$$
z_{\text{ref}} - \varepsilon \le D_L(u,v)
$$

$\varepsilon$ 取多少？太小压不住 acne，太大会导致下一个问题——Peter Panning。

**改进解法**：**斜率偏移**（Slope-Scale Bias）。表面越倾斜、单个 texel 覆盖的深度跨度越大，需要的偏移就越大。

$$
\varepsilon = \max(\varepsilon_{\text{const}},\ k \cdot \tan\theta) = \max(\varepsilon_0,\ k \cdot (1 - N \cdot L))
$$

$\theta$ 是表面法线和光方向的夹角。OpenGL 的 `glPolygonOffset(factor, units)` 就是这个思路，`factor` 乘以斜率、`units` 是常量偏移。DirectX 里 `DepthBias` 和 `SlopeScaledDepthBias` 参数分别对应。

**更好的解法**：**Front-face culling**。第一遍渲染时剔除正面、只画背面。这样阴影图存的是背面深度，比较时**天然自带偏移**（因为薄物体的正面和背面之间就有一段厚度）。缺点是对没有厚度的平面（如树叶、纸片、单面墙）会失效。

## 4. Peter Panning：偏移的代价

偏移加大能压住 acne，但如果加太大，物体的阴影会**脱离物体本身**——脚下的阴影像被挤出去一样漂在远处，物体看起来"悬浮"。这就是 Peter Panning，得名于《彼得潘》里没有影子的小飞侠。

Bias 的调参是"在 acne 和 Peter Panning 之间走钢丝"。工程上通用做法：

1. 用 slope-scale bias 处理绝大多数表面
2. 极薄表面（叶片、栅栏）单独一套小 bias 参数
3. 对可能失去接触感的物体（角色脚部），额外做接触硬化（Contact-hardening）或短距离屏幕空间接触阴影补一层

## 5. 走样与 PCF 软阴影

阴影图是一张有限分辨率的纹理，投影到屏幕上会有**放大/缩小**。缩小时（阴影图远处的 texel 被压到一个屏幕像素以下）出现摩尔纹和闪烁；放大时（一个 texel 覆盖多个屏幕像素）出现**块状硬边**——这是最常见的阴影走样。

硬阴影本身也不真实——现实中的光源都有面积，阴影边缘是**半影**（penumbra）过渡带。

### 5.1 PCF：Percentage-Closer Filtering

Reeves、Salesin、Cook 1987 年提出。传统纹理滤波是先对纹理值做双线性插值再比较——但阴影是二值判断（0 或 1），先插值深度再比较毫无意义（你在插值"最近表面的深度"，插出来的值不代表任何真实表面）。

PCF 的做法是**反过来**：先对每个采样点单独做深度比较得到 0/1，再对这些 0/1 做插值/平均：

$$
\text{shadow}(p) = \frac{1}{N}\sum_{i=1}^{N} \left[ z_{\text{ref}}(p) \le D_L(u_i, v_i) \right]
$$

$3\times 3$ PCF 采 9 个 texel，每个比较得 0/1，平均后阴影边缘有 10 个灰度等级。$5\times 5$ 就有 26 个。视觉上从硬边变成过渡带。

现代 GPU 提供 `sampler2DShadow` / `SampleCmp` 硬件支持——一次采样自动做 4 texel 的 PCF，比手动实现快很多。

### 5.2 PCSS：Percentage-Closer Soft Shadows

PCF 的宽度是固定的——不管遮挡物离接收表面多远，半影宽度都一样。这不符合物理：铅笔悬在纸上 1 mm 时阴影很锐，悬在 10 cm 高时阴影很虚。PCSS（Fernando 2005）用三步模拟物理软阴影：

**第一步 遮挡物搜索**：在阴影图上以片段位置为中心搜索一片区域，找出所有比 $z_{\text{ref}}$ 更近的深度值，求平均 $d_{\text{blocker}}$。

**第二步 半影估计**：根据相似三角形，半影宽度：

$$
w_{\text{penumbra}} = \frac{(z_{\text{receiver}} - d_{\text{blocker}}) \cdot w_{\text{light}}}{d_{\text{blocker}}}
$$

$w_{\text{light}}$ 是光源尺寸（用户参数）。遮挡物离接收器越近 $w$ 越小、越远 $w$ 越大。

**第三步 变尺寸 PCF**：以 $w_{\text{penumbra}}$ 为滤波核宽做 PCF。

PCSS 是"物理直觉+图像空间近似"的经典代表，效果好但代价不小——搜索遮挡物那一步要采样很多 texel。

## 6. VSM 与 ESM：把阴影问题变成滤波问题

PCF 无法与常规纹理滤波管线（mipmap、各向异性、blur）兼容——因为它不是先滤波再判断，而是先判断再滤波。**VSM**（Variance Shadow Maps, Donnelly & Lauritzen 2006）想把阴影变成可以任意预滤波的东西。

想法：不存深度 $z$，而是存 $(z, z^2)$ 两个通道。这两个矩可以像普通纹理一样做 blur、mipmap、SAT。给定滤波区域后：

$$
\mu = E[z], \quad \sigma^2 = E[z^2] - \mu^2
$$

用**切比雪夫不等式**给出遮挡概率上界：

$$
P(z_{\text{ref}} > z) \le \frac{\sigma^2}{\sigma^2 + (z_{\text{ref}} - \mu)^2}
$$

这个值直接作为可见性。好处：可以对 $(z, z^2)$ 做高斯模糊生成软阴影，可以用 SAT 实现任意大小的 box filter，硬件的纹理插值/mip 全部可用。

代价是**漏光**（light leaking）：切比雪夫是上界，不等号在特定几何配置下过于宽松，本该全黑的区域会漏出光来。修正手段有 Light Bleeding Reduction（对结果做重映射 $\max(0, (p - k)/(1-k))$）。

**ESM**（Exponential Shadow Maps, Annen 2008）另辟蹊径，存 $e^{cz}$：

$$
\text{visibility} \approx \frac{E[e^{cz}]}{e^{cz_{\text{ref}}}}
$$

指数比 $z^2$ 更"陡"，漏光更少，但深度差异大时会溢出。工业界多用 VSM 的变体如 EVSM（合并二者）。

## 7. 级联阴影 CSM

方向光的最大痛点是**分辨率永远不够**。一张 2048×2048 的阴影图要覆盖整个视锥体范围（可能几百米深），近处一米内只分到几十个 texel，走样惨不忍睹。

**Cascaded Shadow Maps**（Engel 2006 起流行）的思路：把相机视锥体沿深度方向切成 $N$ 段（通常 3–4 段），每段分配一张独立的阴影图。近处的段覆盖范围小、texel 密度高；远处的段覆盖大、密度低。总内存不变，但近处清晰度大幅提高。

```
    相机视锥体（俯视）
   ─────────────────────────────>  Z
   ┌───┬─────┬──────────┬─────────────────┐
   │ C0│  C1 │    C2    │        C3       │
   └───┴─────┴──────────┴─────────────────┘
    2048  2048     2048        2048
    →密   →中      →疏         →最疏
```

**切分策略**：

- 均匀切分：$z_i = z_n + i(z_f - z_n)/N$。近处浪费。
- 对数切分：$z_i = z_n (z_f/z_n)^{i/N}$。透视意义上均匀，近处过密。
- **PSSM**（Practical Split Scheme, Zhang 2006）：两者加权 $z_i = \lambda z_i^{\log} + (1-\lambda) z_i^{\text{uni}}$。$\lambda \approx 0.5$ 是常用取值。

**级联切换处**会出现分辨率不连续的接缝。做法：在两个级联的重叠区域**混合**采样结果，或者把接缝隐藏在纹理噪声里。

CSM 是几乎所有 3D 引擎的方向光标配。UE、Unity、Frostbite、CryEngine 全用它。移动端因为带宽敏感，级联数通常砍到 2。

## 8. 各技术权衡

| 技术 | 计算成本 | 内存 | 软阴影 | 主要问题 |
|---|---|---|---|---|
| 硬 Shadow Map | 低 | 一张深度 | 无 | 走样、bias |
| PCF | 中 | 同上 | 固定宽 | 边缘统一硬度 |
| PCSS | 高 | 同上 | 物理感 | blocker 搜索昂贵 |
| VSM | 中 | 双通道 | 任意滤波 | 漏光 |
| ESM | 中 | 单通道 | 任意滤波 | 深度差溢出 |
| CSM | 低+级联倍数 | $N$ 倍 | 与上叠加 | 切换接缝 |
| 光追阴影 | 极高 | 加速结构 | 天然 | 需要 RT 硬件 |

工程上典型组合：**CSM + PCF/PCSS**。太阳用 CSM，每级级联内部用 PCF 抹掉硬边；面积光重要时对最近段升级为 PCSS；室内点光源和聚光灯直接 PCF 就够。

## 9. 与管线其他阶段的关系

- 深度写入发生在 [片段处理与输出合并](../图形渲染管线/片段处理与输出合并.mdx) 阶段，Shadow Map 的第一遍就是"只写深度不写颜色"的极端配置。
- 阴影采样在片元着色器执行，与 [基础光照模型](../着色器/基础光照模型.mdx) 中的直接光计算同一时刻——`visibility` 是直接光项前面的系数。
- 硬件光追时代的阴影不用阴影图，改为对每个片段追一根射线到光源，见 [光线追踪基本原理](../光线追踪/光线追踪基本原理.mdx) 和后文 [阴影体及其他阴影技术](./阴影体及其他阴影技术.mdx) 的对比。

## 10. 一段最小可用的 GLSL 片段

阴影采样的片元着色器骨架，供参考实现：

```glsl
float sampleShadow(vec3 posWorld, sampler2DShadow shadowMap,
                   mat4 lightVP, vec3 N, vec3 L) {
    vec4 pL = lightVP * vec4(posWorld, 1.0);
    vec3 ndc = pL.xyz / pL.w;
    vec3 uv  = ndc * 0.5 + 0.5;
    if (uv.z > 1.0) return 1.0;               // 视锥外视为无阴影

    float slope = 1.0 - max(dot(N, L), 0.0);
    float bias  = max(0.005 * slope, 0.0005); // 斜率+常量偏移

    // 硬件 PCF: 3x3 一次采一次比较
    float sum = 0.0;
    vec2 texel = 1.0 / vec2(textureSize(shadowMap, 0));
    for (int y = -1; y <= 1; ++y)
      for (int x = -1; x <= 1; ++x)
        sum += texture(shadowMap,
               vec3(uv.xy + vec2(x, y) * texel, uv.z - bias));
    return sum / 9.0;
}
```

这里 `sampler2DShadow` 让 `texture` 调用自动做深度比较（返回 0/1 或硬件 PCF 的平均值）。9 次采样即得 $3\times 3$ PCF。VSM/PCSS/CSM 都在这个骨架上加东西。

从 1978 到现在，Shadow Map 的骨架一直是**从光源渲染深度，再从相机比较深度**这两句话。所有工程上的花样——bias、PCF、VSM、CSM——都是在为"深度纹理是有限离散的"这一根本限制打补丁。真正跳出这个思路的方案要等到 [阴影体](./阴影体及其他阴影技术.mdx) 和光追硬件，见下一篇。
