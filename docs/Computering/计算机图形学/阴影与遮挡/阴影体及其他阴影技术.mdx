# 阴影体及其他阴影技术：从模板缓冲到屏幕空间遮蔽

[阴影映射](./阴影映射原理与实现.mdx) 是当代实时阴影的主流方案，但它并非唯一的技术路线，也不是所有"阴影"都指同一件事。**直接光阴影**（点/面光源被遮挡产生的硬/软阴影）之外，还有**环境光遮蔽**（周围间接光被几何自遮挡产生的深色接缝）、**接触阴影**（脚下与地板的贴合暗部）。这些不同种类的"暗"在真实感中扮演各自的角色，各有独立的算法家族。本篇把 Shadow Map 之外的阴影相关技术过一遍。

## 1. 阴影体：几何精确的模板法

1977 年，Frank Crow 在 SIGGRAPH 发表 *Shadow Algorithms for Computer Graphics*，提出**阴影体**（Shadow Volume）的概念。这是阴影映射之前就有的方法，走的是完全不同的路线：**在物体空间构造出被光遮挡的三维区域，判断片段是否在这个区域内**。

### 1.1 基本构造

对每个遮挡物体，从光源出发，把物体的**轮廓边**（silhouette edges——法向和光方向内积正负发生翻转的那些边）沿光线方向拉伸到无穷远，形成一个封闭的"体积"，这就是阴影体。任何在阴影体内部的表面，就是被这个物体遮挡的。

```
  光源 *
        \
         \  遮挡物
          █████
         ╱     ╲
        ╱       ╲
       ╱ 阴影体  ╲
      ╱           ╲
     ╱             ╲
   接收面 ────────────
```

### 1.2 模板缓冲计数法

判断"在阴影体内部"用**射线穿越计数**：从摄像机到某个表面点画一条射线，若这条射线穿越阴影体表面的进/出次数不平衡，说明在体内。GPU 实现极简：

**Depth Pass 版本**（早期）：

1. 正常渲染场景到深度和颜色缓冲，光照按无阴影计算（或只加环境项）
2. 关闭颜色写入，开启模板缓冲
3. 渲染阴影体前面（面向摄像机的面）：深度测试通过则模板 +1
4. 渲染阴影体背面：深度测试通过则模板 -1
5. 模板值非零的像素在阴影体内，遮罩掉直接光贡献

**问题**：摄像机进入阴影体内部时，视锥近平面把阴影体截了一刀，计数错位，阴影反相。

**Depth Fail / Carmack's Reverse**（1990s 末，Carmack、Bilodeau、Songhurst 独立发现）：翻转测试方向——**深度测试失败**时增减模板值。等价于"从无穷远反向计数"，视锥近平面不会截，但远平面会——所以阴影体要能延伸到无穷远，投影矩阵需要用无穷远远平面。*Doom 3* 全场用的就是这个方案。

### 1.3 优缺点

**优点**：几何精确、无采样走样、边缘绝对锐利、任意角度都对。

**缺点**：

- **填充率灾难**：阴影体的表面积可能远大于原几何。每个阴影体正反两遍加起来能吃掉屏幕填充预算的大半。摄像机看到的每个像素都可能被大量阴影体几何覆盖。
- **轮廓检测**：动态角色每帧都要重新算轮廓边，CPU/GPU 都得干活。
- **软阴影困难**：模板缓冲是二值的，没有半影自然过渡。要软阴影得多次渲染或引入其他技术。
- **透明物体不友好**：需要不透明轮廓。

工业界从 2005 年前后逐步抛弃阴影体，转向阴影映射。原因是**阴影映射的走样和 bias 问题可以靠 CSM、PCF 逐步改进**（[阴影映射原理与实现](./阴影映射原理与实现.mdx) 全篇都是这些补丁），而阴影体的**填充率上限是硬约束**——分辨率涨到 4K、场景复杂度涨到千万级三角面时，它彻底扛不住。

## 2. 平面投影阴影：最便宜的假影

最古老的实时阴影技巧：假设阴影只落在**已知的平面**上（比如地面、地板），把物体几何按光源方向投影到那个平面上，用暗色再画一遍。

投影矩阵是**奇异矩阵**（rank 3）——把三维几何压扁成平面上的二维分布。构造方式：给定平面 $\mathbf{n} \cdot \mathbf{p} + d = 0$ 和光源位置 $\mathbf{l}$，投影矩阵 $M$ 使得任意点 $\mathbf{p}$ 沿光线方向落到平面上。

```
   L (光源)
    *
    │╲
    │ ╲___
    │     ╲
    │      █ 物体
    │     ╱
    │    ╱
════════▓▓▓══════ 地面 (投影阴影)
```

**优点**：极便宜，只是多画一遍几何加深色。

**缺点**：

- 只能投到一个平面。凹凸不平的地面就穿帮。
- Z-fighting：投影几何和地面共面，需要 polygon offset。
- 阴影**堆叠**：同一物体的多个三角形投影到同一区域后颜色叠加变过暗，需要模板缓冲防重复填充。
- 深度值错误：只是画到地面，物体本身站在阴影上不会自遮挡。

现代引擎里唯一的用武之地是**极简移动端**、**UI 特效**、**手绘风格伪影**。真实场景基本让位给了 Shadow Map。

## 3. 环境光遮蔽：不是阴影的阴影

Shadow Map 和 Shadow Volume 处理的是**直接光被遮挡**。但真实照片中的暗部远不止直接光阴影——桌角与墙的缝、书架里书的间隙、鼻翼两侧的褶皱——这些地方没有明显的"打光"或"遮挡光源"关系，也变暗了。原因是**环境光**（半球所有方向来的漫反射光）在这些几何凹处被自身几何遮住了。这个现象叫**Ambient Occlusion**（AO）。

物理定义：

$$
AO(p) = \frac{1}{\pi}\int_\Omega V(p,\omega) \cdot \cos\theta \, d\omega
$$

$V$ 是可见性函数（1 表示方向 $\omega$ 上能看到远方，0 表示被遮挡），$\cos\theta$ 是朗伯余弦。$AO=1$ 表示完全暴露、$AO=0$ 表示完全封闭。

离线渲染里 AO 靠对每个表面点在半球随机采样射线得到（就是 [光线追踪基本原理](../光线追踪/光线追踪基本原理.mdx) 里的 ambient occlusion 一节）。实时里没这个预算，得从**屏幕空间深度缓冲**里估。

## 4. SSAO：屏幕空间环境光遮蔽

Crytek 在 *Crysis*（2007）里首次大规模使用 **Screen-Space Ambient Occlusion**。核心思路：**已经有屏幕像素的深度了，就用它当粗糙的场景几何近似**。

### 4.1 朴素 SSAO

对每个像素 $p$，在其世界空间位置周围**球形随机采样** $N$ 个点（Crysis 用 16）。把每个采样点反投影回屏幕，读取那个屏幕位置的深度值，比较：

- 采样点深度 > 屏幕深度 → 那个位置的实际几何在采样点前面 → 采样点被遮挡 → 计数 +1
- 否则 → 未遮挡

$AO = 1 - \frac{\text{遮挡计数}}{N}$。

**问题**：球形采样一半的点会在表面**背面**，永远算作遮挡。结果是**平面也会有 50% 的 AO**，整个场景变得灰蒙蒙的。

### 4.2 修正版：半球采样

法线可得的话（G-buffer 里通常有），改为**沿法线方向的半球采样**。这样平面上采样点分布在表面外，遮挡计数只在真正凹处上升。Crysis 后续修正版和几乎所有后来的 SSAO 都用半球。

**采样模式**：随机蓝噪声抖动 + 每像素随机旋转 → 单帧只用少量样本（8–32），后接**双边模糊**去噪。TAA 加持的现代管线可以低到 4 样本，靠时序累积补足。

### 4.3 局限

- **屏幕空间**——看不到的几何不产生遮挡，物体走出视野后其造成的 AO 消失（画面外的椅子不再让墙角变暗）。
- **深度缓冲不含厚度**——一个薄墙和一堵实心墙在深度上一样，采样点穿到"墙后"会被错误算作遮挡。
- **半径受采样密度限制**——想要大半径 AO（大结构上的暗接缝）需要更多样本。

## 5. HBAO：基于水平角的改进

**Horizon-Based Ambient Occlusion**（Bavoil & Sainz, NVIDIA 2008）从更接近物理的角度重写 AO。

对每个像素，沿屏幕上若干**方向线**（通常 4–8 条，每条方向 $\phi$）做步进。每一步读深度、计算相对当前像素的**仰角** $\alpha$。最大仰角就是这个方向上的**地平线角**（horizon angle）。给定该方向水平角 $h(\phi)$ 和切平面角 $t(\phi)$，AO 贡献：

$$
AO(\phi) = \sin(h(\phi)) - \sin(t(\phi))
$$

再对所有方向平均。

```
    surface point
         ↑ 法线
      h  │
       ╲ │
        ╲│_____ horizon (最高被遮挡角)
         ╲
    ─────────── 屏幕方向 φ
```

HBAO 的优势是**物理正确性**——地平线积分是环境光遮蔽积分的解析近似，比 SSAO 的"点是否在深度前"直觉更接近积分本意。视觉上暗部更集中在凹槽处，不会像 SSAO 那样把所有斜面涂灰。

代价是**步进采样**——每方向 8–16 步，总样本量比 SSAO 高。NVIDIA 后来出了 HBAO+ 用交错渲染和空间/时序去噪压成本。

## 6. GTAO：接近解析的答卷

**Ground Truth Ambient Occlusion**（Jimenez et al., Activision 2016）是当前的工业标杆。它在 HBAO 的基础上做了两件事：

1. **修正积分权重**：HBAO 用的 $\sin(h) - \sin(t)$ 忽略了 cosine-weighted 半球的正确形式。GTAO 推导出精确的：

$$
AO(\phi) = \frac{1}{2}\big[\cos(2h_1 - n) + \cos(2h_2 - n) - \cos(n)\cdot 2\big]
$$

其中 $n$ 是法线在方向 $\phi$ 上的投影角，$h_1, h_2$ 是该方向双向的水平角。这个公式匹配了参考路径追踪的 AO 结果。

2. **加上多次反弹近似（GTSO/BentNormals）**：AO 只吃掉一次遮挡，实际上光会反弹回来。GTAO 用一个基于 albedo 的解析近似把间接反弹的能量加回来，避免"过度变黑"。

GTAO + TAA + 单方向单样本每帧，累积几帧后达到接近离线路径追踪的效果。目前 UE、Unity HDRP、Frostbite、id Tech 都上了 GTAO 或其变体。

各代 SS-AO 对比：

| 算法 | 年份 | 样本 | 物理 | 备注 |
|---|---|---|---|---|
| SSAO (Crytek) | 2007 | 16 球采 | 弱 | 首创 |
| SSAO+ 法线半球 | 2008+ | 8–16 半球 | 中 | 消除平面变灰 |
| HBAO | 2008 | 4方向×8步 | 中 | 地平线角积分 |
| HBAO+ | 2013 | 交错去噪 | 中 | 工业化 |
| GTAO | 2016 | 1方向/帧+TAA | 强 | 解析积分+间接反弹 |

## 7. 屏幕空间反射与接触阴影

**Screen-Space Contact Shadows**（SSCS）是短距离屏幕空间射线步进版的阴影补丁——只在片段周围极短范围内步进深度缓冲，判断脚部与地面之间那一点点接触。CSM 因分辨率有限往往在角色脚下漏光，SSCS 补上这个接触感。用极少样本（8–16 步），代价极小。

思路和 SSAO 类似，都是把深度缓冲当成粗糙几何近似。这类"屏幕空间修正"是现代实时渲染补 Shadow Map 短板的标准做法。

## 8. 光线追踪阴影

RTX（NVIDIA 2018）和 DXR/VulkanRT 让 GPU 硬件加速光线求交，阴影问题重新回到 1978 年之前的思路——**对每个片段追一根阴影射线到光源**。

**硬阴影**（点/方向光）：一根射线，命中任何几何就是阴影，否则暴露。天然无走样、无 bias、无 Peter Panning。

**软阴影**（面光源）：对光源做**多重要性采样**，每帧每像素几根射线（1–4 根），命中率作为可见性估计。噪声很大，靠**RT 去噪器**（SVGF、ReSTIR）时序空间过滤重建。

**优点**：

- 阴影质量物理正确，任意面光源
- 无级联、无 bias、无接缝，无 Peter Panning
- 长距离阴影正确（Shadow Map 在几百米外的阴影极不可靠）

**缺点**：

- 需要 RT 硬件（RTX / RDNA2+ / Apple Silicon RT）
- 加速结构（BVH，见 [BVH 与 k-d 树](../光线追踪/加速结构：BVH与k-d树.mdx)）内存开销、动态几何 BLAS 重建成本
- 每像素每帧多根射线仍受性能预算限制，通常和 Shadow Map + SSCS 混合使用

**混合方案（Hybrid Shadows）**：*Metro Exodus Enhanced*、*Cyberpunk 2077 Overdrive*、*Alan Wake II* 的实践路线——太阳光用 RT，环境光遮蔽用 GTAO+RT（RTGI），点光源保留 Shadow Map。这样各取所长。

## 9. 选型对比

| 场景 | 推荐 |
|---|---|
| 移动端、极低预算 | 平面投影 / 低分辨率 Shadow Map |
| 移动/主机中端 | CSM + PCF + SSAO |
| PC 高端无 RT | CSM + PCSS + SSCS + GTAO |
| RT 硬件 | RT 太阳阴影 + Shadow Map 点光 + RT/GTAO 混合 AO |
| 卡通/风格化 | Shadow Map + 后处理描边 |
| 离线渲染 | 全光追 + PT AO |
| VR | Shadow Map 至上（延迟阴影带宽/一致性问题在 VR 放大） |

## 10. 一条脉络

从 Crow 1977 的阴影体，到 Williams 1978 的 Shadow Map，到 Crysis 2007 的 SSAO，到 GTAO 2016，到 RTX 2018 的实时光追——**阴影技术史就是"精确 vs. 可负担"的四十年拉锯**。

- 阴影体精确但填充率上限
- Shadow Map 可扩展但需要一堆补丁
- 屏幕空间 AO 廉价但只能近似
- 光追精确又软阴影，但要硬件

工程上没有"完美方案"，只有"当前预算下最好的组合"。所有引擎最终都是把 3–5 种技术叠加使用——直接光走 [Shadow Map 或 RT](./阴影映射原理与实现.mdx)，接触感靠 SSCS 补，间接光暗部靠 GTAO/RTAO 补，风格化最后一层 shader tint。理解每种技术**擅长解决什么问题、代价花在哪里**，比记住每个公式重要。

阴影的本质是缺失的光。做得好，一切都稳稳落地；做得差，整个虚拟世界飘在半空。
