# RT-2：VLM 协同微调做机器人控制

论文：[RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control](https://arxiv.org/abs/2307.15818)（Google DeepMind，2023）。RT-2 的核心命题很简洁：**机器人控制策略本质上是序列生成问题，跟视觉问答没有本质区别——为什么不用同一个模型来做？**

## 1. 关键创新：协同微调

传统做法是先训一个 VLM 理解世界，再单独训一个策略网络控制机器人——两者分离。RT-2 做的是 **Co-Fine-Tuning（协同微调）**：把机器人轨迹数据直接加入 VLM 微调阶段的混合批次，让同一个模型既学"回答视觉问题"又学"输出电机指令"。

结果：互联网规模的语义知识（物体属性、空间关系、常识推理）可以无缝迁移到机器人决策中。

## 2. 架构

RT-2 实例化了两种 VLM 骨干：

**RT-2-PaLI-X（主变体）**
- 视觉编码器：ViT-22B（220 亿参数）
- 语言模型：32B UL2（编码器-解码器）
- 总参数：**55B**（或轻量版 5B）
- 预训练数据：~10 亿 WebLI 图文对

**RT-2-PaLM-E（对比变体）**
- 视觉编码器：ViT-4B
- 总参数：**12B**

## 3. 动作表示：把控制转成文本 Token

这是 RT-2 最有工程巧思的地方：**不修改任何模型结构**，直接用文本 token 表示机器人动作。

动作空间 8 维：
```
terminate  Δpos_x  Δpos_y  Δpos_z  Δrot_x  Δrot_y  Δrot_z  gripper
```

每个连续维度均匀离散化为 **256 个区间**，对应整数 token 0–255，一条指令变成 8 个整数字符串，例如：
```
"1 128 91 241 5 101 127"
```

Token 分配策略：PaLI-X 直接用词汇表中整数 0–999 对应的 token；PaLM-E 把词汇表里**使用频率最低的 256 个 token** 重新映射为动作 token，尽量不干扰语言能力。

## 4. 训练细节

| 模型 | 学习率 | 批大小 | 训练步数 | 机器人数据占比 |
|---|---|---|---|---|
| PaLI-X-55B | 1e-3 | 2048 | 80K | ~50% |
| PaLI-X-5B | 1e-3 | 2048 | 270K | ~50% |
| PaLM-E-12B | 4e-4 | 512 | 1M | ~66% |

机器人训练数据：RT-1 数据集，约 13 万条轨迹，700+ 任务指令。

推断速度：55B 模型 **1–3 Hz**（云端 TPU），5B 模型约 5 Hz。全程云端部署，机器人本地通过网络调用。

## 5. 实验结果

评估规模：约 6000 条轨迹，含 200+ 已见指令和 280+ 未见泛化指令。

**未见任务成功率对比：**

| 模型 | 已见任务 | 未见任务 |
|---|---|---|
| RT-1 | **92%** | 32% |
| MOO | 75% | 35% |
| **RT-2-PaLI-X-55B** | 91% | **62%** |
| **RT-2-PaLM-E-12B** | 93% | **62%** |

RT-2 在未见任务上约为 RT-1 的 **2 倍**——已见任务两者相当，优势在泛化。

**涌现能力（Emergent Tasks）：** 测试从未出现在机器人训练数据中的指令：

| 模型 | 符号理解 | 推理 | 人物识别 | 平均 |
|---|---|---|---|---|
| RT-1 | 16% | 16% | 20% | 17% |
| **RT-2-PaLI-X-55B** | **82%** | **46%** | **53%** | **60%** |

涌现任务例子：
- "把物体放到数字3上"（没有训练过数字位置映射）
- "我很疲劳，应该拿哪个饮料？"（正确回答：能量饮料）
- "用什么工具像锤子一样敲？"（正确回答：石头）

**规模 + 协同微调消融（未见任务）：**

| 规模 | 训练策略 | 成功率 |
|---|---|---|
| 5B | 从头训练 | 9% |
| 5B | 协同微调 | 44% |
| 55B | 仅微调（无VLM任务） | 52% |
| **55B** | **协同微调** | **63%** |

规模提升和协同微调对泛化都有独立贡献，缺一不可。

## 6. Chain-of-Thought 推理

RT-2 支持在动作 token 前插入自然语言规划步骤：
```
指令：[X]。规划：[中间推理]。动作：[token 序列]
```

通过 VLM 对已有训练数据自动生成规划步骤实现数据增强，无需人工标注。论文描述这种推理能力为"rudimentary"（初级），复杂多步任务仍有明显差距。

## 7. 局限

推断延迟是最大问题：55B 模型 1–3 Hz，无法用于需要快速反馈的动态任务（RT-1 本地可达 3–15 Hz）。全部评估都在 Google 内部特定双臂机器人上进行，跨平台迁移性未验证。256 区间离散化 + 无力控制，对亚毫米级精细操作仍有瓶颈。

更根本的限制是：RT-2 验证了"VLM 能做控制"，但规模代价极高、不开源、不可二次微调——这些问题推动了 [OpenVLA](./05-OpenVLA.mdx) 的诞生。
