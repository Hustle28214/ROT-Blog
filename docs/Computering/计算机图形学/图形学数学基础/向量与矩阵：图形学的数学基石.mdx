# 向量与矩阵：图形学的数学基石

图形学几乎所有东西都可以归结成一句话：**把一堆点乘上一堆矩阵**。顶点变换是矩阵乘法，光照计算是点积，法线校正是叉积，相机旋转是四元数，物理仿真是解线性方程组。学不会向量与矩阵不能说不能做图形学，但每写一行代码都得从头推导，效率低到不能忍。

这一篇不打算像线性代数教材那样从公理开始，而是围绕图形学场景里真实用到的操作展开——**每个概念都有一个具体的图形学用途**。

## 1. 向量：位置与方向的统一语言

向量在图形学里同时承担两种角色：**位置**（point）和**方向**（direction）。数学上都是 $\mathbb{R}^3$ 里的三元组 $(x,y,z)$，但语义完全不同：

- 点在平移下会变化：$P + t = P'$
- 方向在平移下不变：$\vec{v} + t = \vec{v}$

这个区别在齐次坐标里显式化了——点写成 $(x,y,z,1)$，方向写成 $(x,y,z,0)$，第四维决定了平移矩阵会不会影响它。这一点会在[坐标空间变换](./坐标空间变换：从模型到屏幕.mdx)里详细展开。

### 1.1 长度、单位化、距离

$$
\|\vec{v}\| = \sqrt{x^2+y^2+z^2}, \quad \hat{v} = \frac{\vec{v}}{\|\vec{v}\|}
$$

单位化几乎每帧都要做无数次——法线必须是单位向量，光照方向必须是单位向量，否则点积就不是余弦值。除法开销大，工程上常见的技巧：

- 用平方长度 $\|\vec{v}\|^2$ 比大小（比距离时不用开方）
- 快速倒数平方根（Quake III 的 `0x5f3759df` 魔数）
- SIMD 一次算 4 个分量

现代 GPU 有硬件 `rsqrt` 指令,开销和普通乘法差不多,魔数已经是历史,但那段代码仍然是"理解浮点位表示"的经典教材。

## 2. 点积：几何测量的瑞士军刀

$$
\vec{a}\cdot\vec{b} = a_xb_x+a_yb_y+a_zb_z = \|\vec{a}\|\|\vec{b}\|\cos\theta
$$

点积是标量,但编码了角度信息。图形学里它出现在几乎所有的"测量"场景:

| 用途 | 表达式 | 说明 |
|---|---|---|
| 判断同向 | $\vec{a}\cdot\vec{b} > 0$ | 夹角小于 90° |
| 光照强度 | $\max(0, \vec{n}\cdot\vec{l})$ | Lambert 漫反射 |
| 投影长度 | $\vec{a}\cdot\hat{b}$ | $\vec{a}$ 在 $\vec{b}$ 上的分量 |
| 点到平面距离 | $\vec{n}\cdot\vec{p}+d$ | 平面方程 $\vec{n}\cdot\vec{x}+d=0$ |
| 反射向量 | $\vec{r}=\vec{d}-2(\vec{d}\cdot\vec{n})\vec{n}$ | 镜面反射 |
| 视锥剔除 | 顶点对每个面 $\vec{n}\cdot\vec{p}+d$ 的符号 | 六个平面同号则可见 |

Lambert 定律最能体现点积的物理含义。表面法线 $\vec{n}$ 和光源方向 $\vec{l}$ 都单位化以后,$\vec{n}\cdot\vec{l}$ 直接就是入射光的余弦——这正是 [BRDF](../着色器/BRDF与材质系统.mdx) 里能量守恒的核心。

## 3. 叉积:构造正交向量的机器

$$
\vec{a}\times\vec{b} = \begin{vmatrix}\vec{i}&\vec{j}&\vec{k}\\a_x&a_y&a_z\\b_x&b_y&b_z\end{vmatrix}
= \begin{bmatrix}a_yb_z-a_zb_y\\a_zb_x-a_xb_z\\a_xb_y-a_yb_x\end{bmatrix}
$$

叉积产生一个**同时垂直于 $\vec{a}$ 和 $\vec{b}$** 的向量,方向由右手定则决定,长度 $\|\vec{a}\|\|\vec{b}\|\sin\theta$ 等于两向量张成的平行四边形面积。

图形学里的典型用途:

- **计算三角形法线**:$\vec{n}=(\vec{v}_1-\vec{v}_0)\times(\vec{v}_2-\vec{v}_0)$
- **构造切线空间**:法线贴图需要 TBN(Tangent-Bitangent-Normal)三元组,B 通常由 T 和 N 的叉积得到
- **判断顶点绕序**(CCW/CW):三角形面积的符号决定了背面剔除
- **计算力矩、角动量**:物理仿真里的核心

叉积**不满足交换律**($\vec{a}\times\vec{b}=-\vec{b}\times\vec{a}$),这正是"绕序"这个概念的数学根源。OpenGL 默认逆时针为正面,DirectX 默认顺时针,底层都是叉积符号的约定差异。

```
      ^ b×a (指向屏幕外)
      │
      │
      └─────> a
     ╱
    ╱
   ↙ a×b (指向屏幕内)
```

## 4. 矩阵:线性变换的表格化

一个 $n\times n$ 矩阵编码了一个 $\mathbb{R}^n\to\mathbb{R}^n$ 的线性变换。**列向量就是基向量变换后的位置**——这是理解矩阵最直观的方式。

$$
M = \begin{bmatrix}|&|&|\\M\vec{e}_1&M\vec{e}_2&M\vec{e}_3\\|&|&|\end{bmatrix}
$$

标准正交基 $\vec{e}_1,\vec{e}_2,\vec{e}_3$ 被 $M$ 送到哪里,矩阵的列就是什么。看到一个矩阵,先看它的三列——你就知道它对空间做了什么。

### 4.1 常用 3x3 变换

**缩放**:

$$
S = \begin{bmatrix}s_x&0&0\\0&s_y&0\\0&0&s_z\end{bmatrix}
$$

**绕 z 轴旋转**:

$$
R_z(\theta) = \begin{bmatrix}\cos\theta&-\sin\theta&0\\\sin\theta&\cos\theta&0\\0&0&1\end{bmatrix}
$$

绕 x/y 的旋转矩阵结构对称。任意轴旋转有 Rodrigues 公式——但真到工程里几乎没人手写 Rodrigues,直接用四元数或从两个正交向量构造(见第 6 节)。

**切变**(shear)、**投影**、**反射**也都是 3x3 矩阵。它们的共同特征:**保留原点**。这就是"线性"变换的定义——原点不动。想让原点动,必须升维。

### 4.2 平移为什么必须齐次

平移 $\vec{p}\to\vec{p}+\vec{t}$ 不是线性变换(原点动了),所以在 3x3 里表达不出来。解决办法是加一维,把点写成 $(x,y,z,1)$:

$$
T = \begin{bmatrix}1&0&0&t_x\\0&1&0&t_y\\0&0&1&t_z\\0&0&0&1\end{bmatrix}, \quad T\begin{bmatrix}x\\y\\z\\1\end{bmatrix} = \begin{bmatrix}x+t_x\\y+t_y\\z+t_z\\1\end{bmatrix}
$$

方向向量的 $w=0$,所以 $T\vec{v}=\vec{v}$——方向不受平移影响,正好符合物理直觉。齐次坐标不只是一个技巧,而是**射影几何**的原生表达。透视投影里 $w$ 会变成有意义的非零值,除以 $w$ 才回到欧氏空间——这是[坐标空间变换](./坐标空间变换：从模型到屏幕.mdx)的核心。

## 5. 矩阵组合与顺序

$$
(AB)\vec{v} = A(B\vec{v})
$$

从右往左读:先应用 $B$,再应用 $A$。图形学里典型的 MVP 变换:

$$
\vec{v}_{\text{clip}} = P\cdot V\cdot M\cdot\vec{v}_{\text{local}}
$$

从右到左:模型矩阵 $M$ 把物体从局部空间搬到世界,视图 $V$ 搬到相机,投影 $P$ 搬到裁剪空间。

**矩阵乘法不满足交换律**——先转再平移和先平移再转结果完全不同:

```
先旋转再平移(绕原点转,然后走到新位置):
       ╱→ P'
      ╱
   * P
     
先平移再旋转(先走到新位置,再绕原点转):
              ↗ P'
             ╱ 
   *────────>P
```

图形学里 90% 的"物体位置不对"的 bug 都是矩阵顺序写反。经验:先想清楚"这个变换在什么坐标系里做",再决定乘的位置。

### 5.1 逆矩阵与转置

- **正交矩阵**(旋转矩阵):$R^{-1}=R^T$,极快
- **齐次变换**(旋转 + 平移):$T^{-1}$ 可以显式写出,不用 LU 分解
- **一般 4x4**:才需要真求逆

法线向量的变换很微妙:如果模型矩阵含**非均匀缩放**,法线不能直接用模型矩阵变换,否则会不再垂直于表面。正确做法是用 $(M^{-1})^T$——法线矩阵。推导:切向量 $\vec{t}$ 变换为 $M\vec{t}$,法线要保持 $\vec{n}\cdot\vec{t}=0$,即 $\vec{n}'\cdot(M\vec{t})=0$,得 $\vec{n}'=(M^{-1})^T\vec{n}$。

## 6. 四元数:旋转的最佳表示

三种旋转表示:

| 表示 | 存储 | 组合 | 插值 | 万向锁 |
|---|---|---|---|---|
| 欧拉角 | 3 值 | 麻烦 | 逐分量,不平滑 | 有 |
| 3x3 矩阵 | 9 值 | 矩阵乘 | 不能直接插值 | 无 |
| 四元数 | 4 值 | 四元数乘 | slerp 平滑 | 无 |

四元数 $q=w+xi+yj+zk$,四个实数,虚部满足 $i^2=j^2=k^2=ijk=-1$。**单位四元数**($w^2+x^2+y^2+z^2=1$)可以表示旋转:绕单位轴 $\vec{u}$ 旋转 $\theta$ 对应

$$
q = \cos\frac{\theta}{2} + \sin\frac{\theta}{2}(u_xi+u_yj+u_zk)
$$

关键运算:

- **组合两次旋转**:$q_2 q_1$(四元数乘,右侧先做)
- **旋转向量**:$\vec{v}' = q\vec{v}q^{-1}$(把 $\vec{v}$ 视为纯虚四元数)
- **求逆**:单位四元数 $q^{-1}=q^*=w-xi-yj-zk$

**为什么四元数是骨骼动画的标配**:关键帧之间的插值。矩阵直接线性插值会得到非旋转矩阵(变形),欧拉角插值会走弯路且遇万向锁,只有四元数的球面线性插值(slerp)沿最短弧,速度均匀:

$$
\text{slerp}(q_0,q_1,t) = \frac{\sin((1-t)\Omega)}{\sin\Omega}q_0 + \frac{\sin(t\Omega)}{\sin\Omega}q_1
$$

$\Omega$ 是两四元数的夹角。$q$ 和 $-q$ 表示同一个旋转,插值前要选点积正的那个,不然会走"长路"。

### 6.1 万向锁到底是什么

欧拉角用三个绕轴旋转组合表示任意旋转:$R=R_z(\gamma)R_y(\beta)R_x(\alpha)$。当 $\beta=\pm 90°$ 时,$R_x$ 和 $R_z$ 变成同一个轴——原本三个自由度塌成两个。物理上表现为陀螺仪的两个环重合,失去一个转动自由度,故名"gimbal lock"。四元数用四维表示三维旋转本身就是过参数化(单位约束占掉一维),没有奇异点。

## 7. 应用:构造一个"看向"矩阵

给定相机位置 $\vec{e}$、目标点 $\vec{t}$、上方向 $\vec{u}_{\text{up}}$,构造视图矩阵。这个例子把上面的东西全部串起来。

```
1. 前向:  f = normalize(t - e)      // 单位化
2. 右向:  r = normalize(f × u_up)   // 叉积构造正交
3. 上向:  u = r × f                 // 再叉积,得完美正交基
4. 组装矩阵:
       ┌ r.x  r.y  r.z  -r·e ┐
       │ u.x  u.y  u.z  -u·e │
   V = │-f.x -f.y -f.z   f·e │
       └  0    0    0     1  ┘
```

第 4 步的负号来自"视图矩阵是相机变换的逆"——相机在世界坐标是 $\vec{e}$,视图空间里相机在原点,所以整个世界要往反方向平移。旋转部分正交,逆等于转置,所以直接写行向量为原基向量。这就是 `gluLookAt` 的全部内容。

## 8. 图形学数学的工程化经验

- **列主序 vs 行主序**:OpenGL、GLSL、Eigen 是列主序,DirectX、Unity 内部是行主序。同一个矩阵内存布局不同,乘顺序也可能反过来。跨引擎移植时先搞清楚这个再谈其他。
- **精度**:GPU 主要用 float32,近处物体没问题,但世界很大时(月球、太阳系尺度)会出现 z-fighting、抖动。行星级渲染要做**相对相机的坐标**,把大数减掉。
- **SIMD 友好**:向量按 16 字节对齐,矩阵按 4x4 存(哪怕只用 3x3),便于 SSE/NEON 单指令处理。
- **不要手推**:GLM、Eigen、DirectXMath 已经把常用变换写好且测过。除非你在做数学推导,否则不要自己实现矩阵求逆。

这些不是可选项而是工程默认——图形学里的 bug 一半来自数学错,另一半来自数学对了但数值精度不够。
