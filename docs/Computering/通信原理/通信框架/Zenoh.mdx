## Zenoh简介

Zenoh（Zero Overhead Network Protocol）是 ZettaScale（也是 ROS 2 默认中间件 Cyclone DDS 的团队）做的一个新框架。经历了智驾领域的多年沉淀，他们在 2021 年 11 月发布了 Zenoh 1.0 版本。

这是一个基于Rust设计的非常精巧又五脏俱全的通信框架，把发布/订阅、查询/响应、KV 存储三种通信模式统一到了一起，特别的点在于这个通信模式可以从云端通到MCU，不需要转译的中间件，解决了嵌入式系统和云端通信日常面临的“有太多话想说，又不好全说，又不好不说”的问题。

它有几个值得专门拎出来说说的点：

- **统一的原语**。在 Zenoh 里，`pub/sub`、`get/reply`、`KV` 都是同一套 API，只是参数不一样。不用再纠结"这个场景该用哪个框架"。
- **协议极轻**。Zenoh 的字节级协议非常紧凑，一个 header 只有 7 字节。能在 TCP、UDP、QUIC、WebSocket、串口、共享内存之间无缝切换——是的，**串口也能跑 Zenoh**，这是它对 IoT/机器人特别友好的原因。
- **资源占用小**。官方给的嵌入式参考实现能在 Cortex-M4 + 1MB Flash 上跑起来。
- **地理位置感知的路由**。它的路由层原生支持 locality/topology 策略，可以声明"我这条数据是边缘产生的，请就近处理"，这在云边协同、车队管理这种场景下非常顺手。
- **与 DDS/ROS 2 的关系**。ZettaScale 自己就是 ROS 2 通信栈的供应商，所以 Zenoh 在设计时直接考虑了怎么桥 DDS、怎么当 ROS 2 的下一代传输层（rmw_zenoh 已经在实验中了）。

一句话总结：**Zenoh 想做的事是"通信中间件的统一接口 + 跨域透明"**——不管是云、边缘还是嵌入式 MCU，都用同一套 API、同一个协议去交换数据。如果你正在为"机器人控制器 ↔ 网关 ↔ 云端"三段链路选型，它值得进短名单。

## Zenoh 的语法形式

### 键表达式 Key Expression

键表达式是一个 UTF-8 字符串，用于在 Zenoh 系统中标识一个或多个资源。

它类似路径结构，并支持结构化通配符来做模式匹配。

完整语法见：https://spec.zenoh.io/spec/1.0.0/appendix/grammar.html

```text
key-expr     = chunk *("/" chunk)
chunk        = 1*(unreserved / pct-encoded) / wild1 / wildN
wild1        = "*"
wildN        = "**"
unreserved   = ALPHA / DIGIT / "-" / "_" / "." / "~" / "@" / "$"
pct-encoded  = "%" HEXDIG HEXDIG
```

一个格式良好的键表达式满足以下所有条件：

- 末尾没有 /。
- 没有空块（即 // 无效）。
- 不得与另一个 * 或块相邻（例如 a// 无效）。
- 总长度必须至少为 1 个字符。

:::info

本地应用传来的 key expression，必须检查合法性，不合法就拒绝。网络上收到的 key expression，推荐也检查合法性，但规范不强制。

:::

### 通配符 Locators

| 通配符 | 名称  | 匹配规则                                                         | 示例                                                                       |
| ------ | ----- | ---------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `*`    | wild1 | 精确匹配一个块。这个块是非空、且不包含 `/` 的字符序列。        | `a/*/c` 匹配 `a/b/c`、`a/xyz/c`；不匹配 `a/b/d/c`、`a//c` |
| `**`   | wildN | 匹配零个或多个完整块。可以是空序列，也可以是任意由 `/` 分隔的块序列。 | `a/**/c` 匹配 `a/c`、`a/b/c`、`a/b/d/c`；`**` 单独使用时匹配任意键表达式，包括空字符串 |

### 查询参数

```text
parameters = [ parameter *( ";" parameter ) ]
```

`parameters` 是可选的，也就是说可以为空，因为外面有 `[ ]`。

如果不为空，必须由一个 `parameter` 开头。后面可以跟0个或多个 `; parameter`。

合法形式：

```text
key
key=value
key1=value1;key2=value2
key1;key2=value2;key3
```
一个 `parameter` 要么是 `key`，要么是 `key=value`。
