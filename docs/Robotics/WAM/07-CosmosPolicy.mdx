论文：[Cosmos Policy: Fine-Tuning Video Models for Visuomotor Control and Planning](https://arxiv.org/abs/2601.16163)，NVIDIA，2026 年 1 月。代码和模型在 [research.nvidia.com/labs/dir/cosmos-policy](https://research.nvidia.com/labs/dir/cosmos-policy/)。

## 1. 先说结论

Cosmos Policy 走了一条跟 [DiT4DiT](./06-DiT4DiT.mdx) 完全不同的路：**不改视频模型架构，把 action、future state、value 全部编码成 latent frame，塞进同一个 video diffusion 序列里一起生成**。

单阶段 post-training，LIBERO 98.5%，RoboCasa 67.1%，ALOHA 2 四个真机双手任务平均 93.6%。还能用 rollout 数据继续 refine world model 和 value，做 test-time best-of-N planning。

但代价也明确：[MotionWAM](./01-MotionWAM.mdx) 论文里直接拿它做对照——同参数量级（2.0B）只有 **0.7 Hz**，MotionWAM 4.9 Hz，因为 Cosmos Policy 必须迭代 denoise 未来视频才能出动作，DiT4DiT/MotionWAM 只读中间特征。

## 2. 核心思路：action 也是一帧

现有工作把 video model 适配成 robot policy，往往需要多阶段 post-training 和额外的 action 生成模块。Cosmos Policy 的做法很朴素：

> 既然 Cosmos-Predict2 本来就会生成 latent video，那把 robot action、proprioceptive state、value 也 encode 成 latent frame，跟 future image frame 排成一条序列，用同一个 diffusion objective 联合建模。

输入：多视角 RGB + 语言指令 + 当前 proprio。
输出三条并行的 latent 序列：

1. **Action chunk**：未来 $H$ 步关节/夹爪命令；
2. **Future state**：未来时刻的 proprio + 图像观测；
3. **Value**：未来状态的 expected cumulative reward。

三条都是 VAE latent 空间里的"帧"，DiT 一次 denoise 全吐出来。没有新模块，没有 separate action head，就是 video diffusion 本身。

## 3. 两种用法：直接策略 vs 规划

**Direct policy**：给定观测和语言，denoise 出 action chunk，执行第一个 action 或整个 chunk，然后重新推理。这就是标准的 receding horizon。

**Model-based planning**：需要两个模型 checkpoint——

- Policy model：出 action proposal；
- Planning model：给定 (当前状态, 候选 action)，预测 future state 和 value。

Test-time 做 best-of-N：从 policy 采样 $N$ 个 action 候选，planning model 给每个候选打分（value），选最高的执行。Rollout 数据还可以继续 fine-tune planning model，让 world model 和 value function 越来越准。

这个设计把 MuZero/TD-MPC 那套"短视野 rollout + 价值评估"又搬回了 video diffusion 框架里，只是 rollout 的对象是 latent video frame 而不是 RSSM latent。

## 4. 实验

仿真：LIBERO 98.5%，RoboCasa 67.1%，超过 Diffusion Policy、ACT、GR00T、$\pi_{0.5}$ 等 baseline。RoboCasa 上 67.1% 比 DiT4DiT 的 50.8% 高，但训练数据和 setting 不完全一样，不能直接当"完整 denoise 比 hook 特征更好"的证据。

真机 ALOHA 2：四个双手任务平均 93.6%，超过同数据微调的 diffusion policy 和 VLA。Planning 模式在难任务上还能再涨一截。

## 5. 跟 DiT4DiT / MotionWAM 的对照

这三篇放在一起看，WAM 领域目前有两条清晰路线：

| | Cosmos Policy | DiT4DiT / MotionWAM |
| --- | --- | --- |
| 架构改动 | 无，action 当 latent frame | 加 Action/Motion DiT |
| 训练阶段 | 单阶段（+ 可选 planning fine-tune） | DiT4DiT 联合训练；MotionWAM 三阶段 |
| 推理 | 完整 video denoise | 一次前向截 hidden state |
| 频率 | 0.7 Hz（2B, A100） | DiT4DiT 6 Hz；MotionWAM 4.9 Hz |
| 额外能力 | future state + value + planning | 主要靠 action 分支 |
| 真机验证 | ALOHA 2 桌面双手 | DiT4DiT G1 操作；MotionWAM G1 全身 |

Cosmos Policy 的优势是简洁——一个模型、一个 objective、还能做 planning。DiT4DiT/MotionWAM 的优势是频率和全身控制。我的判断是：固定基座 manipulation 如果不在乎 0.7 Hz，Cosmos Policy 的统一建模很优雅；人形 loco-manipulation 这种需要实时闭环的场景，hook 特征那条路目前是唯一能用的。

## 6. 局限

跟所有 video diffusion policy 一样，频率是硬瓶颈。0.7 Hz 意味着每个 action chunk 之间隔 1.4 秒，靠 chunk 内部插值撑闭环，动态交互任务会很吃力。另外 value 和 future state 的质量完全绑定在 video denoise 质量上，video 模型幻觉会直接传到 planning 打分上，best-of-N 选出来的"最优" action 可能只是 video 模型觉得最好看的那个，不一定是物理上最稳的那个。
