# 顶点处理与图元装配

顶点是几何的最小载体。一个网格再复杂，本质也是一堆顶点加上"谁跟谁连成三角形"的连接关系。GPU 管线的前半段——从 IA 到 PA——就是把这些顶点按照相机的视角变换、组装、裁剪，最后交给光栅器一批**屏幕空间里位置确定的三角形**。这一步做好了，光栅化和着色才有意义。

## 1. 顶点是什么

在图形学里，顶点不只是"三维坐标"这么简单。一个顶点是一个**属性束**（attribute bundle），常见的包括：

| 属性 | 类型 | 用途 |
|---|---|---|
| position | vec3 | 模型空间坐标 |
| normal | vec3 | 法线，用于光照 |
| tangent | vec4 | 切线，w 存副切线方向 |
| uv0, uv1 | vec2 | 纹理坐标 |
| color | vec4 | 顶点色 |
| bone weights | vec4 | 骨骼蒙皮权重 |
| bone indices | uvec4 | 骨骼索引 |

一个"胖顶点"可能占 60–80 字节。1000 万顶点的模型，顶点缓冲就是接近 1 GB——所以工业界会用**紧凑格式**（法线用 8 位、UV 用 16 位半精度、切线压成 quaternion），把每顶点压到 20 字节左右。

### 1.1 顶点缓冲与索引缓冲

一个立方体有 8 个物理顶点，但它有 12 个三角形、36 个顶点位置的引用。用**索引缓冲**（Index Buffer）把 8 个顶点数据存一份，另开一个 36 个 int 的表指过来：

```
Vertex Buffer:  [V0][V1][V2][V3][V4][V5][V6][V7]
Index Buffer:   [0,1,2, 0,2,3, 4,5,6, ...]   // 36 个整数
```

索引缓冲有两个副作用值得一提：

1. **顶点缓存复用**：GPU 有个 post-transform vertex cache（十几到几十项），如果连续几个三角形引用了同一个索引，VS 只算一次结果，其余从缓存里拿。工业界会对索引缓冲做 Forsyth 或 Tom Forsyth's linear-speed vertex cache optimization 一类的排序，让缓存命中率最大化
2. **只有共享属性的顶点才能被"同一个"索引指到**——如果法线在两个三角形接缝处不同（硬边），那就必须存两份物理顶点。所以实际顶点数比拓扑顶点数往往多 20–50%

## 2. 顶点着色器 VS 在做什么

VS 是一个"每顶点独立执行"的函数：

```glsl
in vec3 aPos;
in vec3 aNormal;
in vec2 aUV;
uniform mat4 uModel, uView, uProj;
uniform mat3 uNormalMat;   // = transpose(inverse(mat3(uModel)))

out vec3 vWorldPos;
out vec3 vNormal;
out vec2 vUV;

void main() {
    vec4 world = uModel * vec4(aPos, 1.0);
    vWorldPos = world.xyz;
    vNormal   = uNormalMat * aNormal;
    vUV       = aUV;
    gl_Position = uProj * uView * world;   // 裁剪空间
}
```

规矩很简单：一个顶点进、一个顶点出，`gl_Position` 必须写。VS 的输出会被下游插值给片段。

### 2.1 该在 VS 还是 FS 里算

工程直觉：**能在 VS 算的就别放 FS**。假设一个屏幕上占 1000 像素的三角形，VS 跑 3 次、FS 跑 1000 次。把 MVP 乘法之类的挪到 VS，能省下几百倍的运算。但要小心：

- **线性量**才能用 VS 算完插值（比如世界坐标），因为线性插值和线性变换可交换
- **非线性量**必须 FS 算（比如归一化法线——先插值再归一化，因为顶点法线插值后长度不再是 1）
- 涉及非线性函数（`normalize`、`pow`、`exp`）的都得挪回 FS 或者接受精度损失

早期 GPU 的 VS 便宜、FS 贵，所以 Gouraud shading 把光照放 VS 算完再插值——阴影带比 Phong 明显但快很多。今天 FS 已经不算贵了，Phong shading 是默认。

### 2.2 法线变换的坑

顶点位置用 `M` 变换，法线要用 $(M^{-1})^T$ 变换，理由在 [向量与矩阵：图形学的数学基石](../图形学数学基础/向量与矩阵：图形学的数学基石.mdx) 里推过——非等比缩放下法线不能直接乘 $M$，否则会歪。上层引擎通常在 CPU 端就算好 normal matrix 传进来，避免 VS 里做矩阵逆。

## 3. 图元类型

VS 出来的顶点按驱动指定的**图元拓扑**（Primitive Topology）组装。基本几种：

```
Point List:          . . . . . .        每个顶点一个点
Line List:           .──.  .──.  .──.   顶点两两成线
Line Strip:          .──.──.──.──.      前后接
Triangle List:       每 3 顶点一个三角形
Triangle Strip:      V0-V1-V2-V3-...    V(i)V(i+1)V(i+2) 每次滑一格
Triangle Fan:        V0 固定为中心      V0-V(i)-V(i+1)
```

Triangle Strip 和 Fan 比 List 省顶点——一个 N 个三角形的 strip 只要 N+2 个顶点，而 list 要 3N 个。但 DX10 起 Fan 被砍了，现代硬件基本只优化 List，索引缓冲 + list 已经是通吃方案。

有些高级拓扑（Line List with Adjacency、Triangle List with Adjacency）给几何着色器用，因为 GS 需要看到邻接三角形才能挤阴影体。

## 4. 齐次裁剪

VS 输出的 `gl_Position` 是**四维齐次坐标**，还没做透视除法。为什么？因为**裁剪必须在除法之前做**。

考虑一个三角形横跨相机前后：一个顶点 $w > 0$（在相机前），一个 $w < 0$（相机后）。透视除法 $x/w$ 会把 $w<0$ 的顶点翻到反方向，正常绘制就完全崩了——出现"物体贴到脸上又对称到背后"的 bug。裁剪要在齐次空间里干完。

### 4.1 视锥的齐次表示

透视投影后视锥变成规则立方体（OpenGL: $[-1,1]^3$，D3D/Vulkan: $[-1,1]^2 \times [0,1]$），在齐次空间里表现为六个不等式：

$$
-w \le x \le w,\quad -w \le y \le w,\quad -w \le z \le w \;(\text{GL})
$$

或对 D3D：$0 \le z \le w$。六个视锥面对应六次"切三角形"。

### 4.2 Sutherland-Hodgman

对每个视锥面 $\pi$，遍历多边形的每条边 $(V_i, V_{i+1})$：

```
for each edge (Vi, Vi+1):
    if Vi 在内 and Vi+1 在内:  输出 Vi+1
    if Vi 在内 and Vi+1 在外:  输出交点
    if Vi 在外 and Vi+1 在内:  输出交点, Vi+1
    if Vi 在外 and Vi+1 在外:  无输出
```

一个三角形被切完后可能变成 3–9 边形，硬件光栅器再把它三角形化。交点处的**所有顶点属性**（不只是位置）都要按参数 $t$ 线性插值：

$$
t = \frac{d(V_i)}{d(V_i)-d(V_{i+1})}, \quad V_{\text{new}} = (1-t)V_i + t V_{i+1}
$$

其中 $d(\cdot)$ 是齐次距离函数。属性插值这一步是**在齐次空间线性**，光栅化里的属性插值则要做**透视校正**，两码事。

### 4.3 Guard band

真裁剪代价不便宜——切一个三角形可能生出几个新的。硬件的技巧是**扩大裁剪区域**（guard band，例如把左右上下界扩到 $\pm 8w$），只裁那些真的会导致溢出屏幕坐标寄存器的三角形，其余全部让光栅器自己扫（反正扫到屏幕外的采样点会被丢弃）。这叫 **scissor-based rejection**，实测能省 90% 的显式裁剪工作。

## 5. 透视除法与视口变换

裁剪之后，每个顶点从齐次坐标变到 NDC：

$$
(x_c, y_c, z_c, w_c) \;\to\; \left(\frac{x_c}{w_c}, \frac{y_c}{w_c}, \frac{z_c}{w_c}\right)
$$

结果在 $[-1,1]^3$（GL）里。然后视口变换：

$$
x_s = \frac{W}{2}(x_n + 1) + x_0, \quad y_s = \frac{H}{2}(y_n + 1) + y_0, \quad z_s = z_n
$$

$(W,H)$ 是视口宽高，$(x_0,y_0)$ 是视口左下（D3D 是左上）。这一步固定功能，程序员管不着。

$w_c$ 本身会保留下来给后面用——**透视校正插值**必须用 $1/w$ 才能算对。见下一章的详细推导。

## 6. 背面剔除

三维物体的背面对相机不可见，画出来纯浪费。判断依据是三角形在**屏幕空间的绕序**：

$$
\text{signed area} = \frac{1}{2}\left[(x_1-x_0)(y_2-y_0) - (x_2-x_0)(y_1-y_0)\right]
$$

正的是逆时针（CCW），负的是顺时针（CW）。约定一个方向为正面（GL 默认 CCW 正面），反的丢掉。

背面剔除通常能砍掉一半三角形，是最便宜的性能优化——但**要求模型是闭合的**、**没有双面材质**。透明物体、纸片、树叶要关掉背面剔除，否则从背后看就消失了。

绕序也依赖于变换矩阵——如果 model 矩阵含有奇数次镜像（$\det M < 0$），绕序会翻转，需要在渲染状态里切换 winding。

## 7. 视锥剔除 vs 齐次裁剪

这两件事经常混。**视锥剔除**（Frustum Culling）是 CPU 端在提交 draw call 之前做的粗筛——用包围盒和视锥做相交测试，整个物体在视锥外就不提交。**齐次裁剪**（Clipping）是 GPU 内 PA 阶段做的精修——三角形与视锥面精确求交、切开。

一般层次是：

```
应用层 (CPU):
  1. 大场景管理 (Octree/BVH)
  2. 视锥剔除 (整物体)
  3. 遮挡剔除 (Occlusion Culling)
GPU 端:
  4. 齐次裁剪 (每三角形)
  5. 背面剔除
  6. 光栅化阶段 scissor/viewport 剔除
```

多级剔除并不冗余——层级越高越粗越便宜，逐级过滤才能让 GPU 只处理真正可见的几何。

## 8. VS 的输入输出格式与插值声明

FS 需要每个片段的插值属性，插值方式在 shader 里声明：

| 修饰符 | 行为 |
|---|---|
| （默认）`smooth` | 透视校正线性插值 |
| `noperspective` | 屏幕线性插值（不做校正） |
| `flat` | 不插值，全片段取 provoking vertex 的值 |
| `centroid` | 采样点在 MSAA 覆盖区内 |

用 `flat` 是有意义的——比如整数属性（材质 ID）、法线量化后的正交基索引，插值出来是无意义的浮点，只能取一个顶点的值。

## 9. 一次数据流示例

假设画一个正方形（两个三角形，4 个顶点索引 6 个）：

1. **IA**：从顶点缓冲读 4 个顶点，按索引 [0,1,2, 0,2,3] 组成两个三角形
2. **VS**：4 次执行（有 cache 命中），每个顶点变换到裁剪空间
3. **裁剪**：若两个三角形都在视锥内，跳过
4. **透视除法**：4 个顶点 $/w$，得 NDC
5. **视口变换**：4 个顶点 $\to$ 屏幕像素坐标
6. **背面剔除**：算屏幕空间面积，符号对了就通过
7. 交给光栅器

VS 在 IA 之后、PA 之前，硬件上通常 VS 输出直接进一个 SIMD 寄存器组，PA 从这里读顶点做剪裁——没有大的中间缓冲。

## 10. 与后续阶段的接口

顶点处理段的输出是：

- 一批屏幕空间内的三角形（各顶点带全套插值属性）
- 每顶点的 $1/w$（供透视校正）
- 每顶点的 $z$（深度值）

这些交给 [光栅化：三角形如何变成像素](./光栅化：三角形如何变成像素.mdx) 生成片段。到那一步之后，几何信息就基本被扔掉了，剩下的都是像素级的事情。

VS 是一切的开端。写 VS 时脑子里要装着：这里的每一次乘法乘以顶点数就是每帧的负担；这里的每一个 varying 都会占用光栅器的插值器带宽；这里的每一个矩阵都最好在 CPU 端合并好了再传上来。管线的性能，从 VS 开始就已经在被决定。
