# 光栅化：三角形如何变成像素

光栅化是整条渲染管线里唯一一步"从连续几何跳到离散像素"的操作。它决定了一个三角形能覆盖哪些像素、每个像素处的深度和插值属性是多少、多重采样的采样点应该怎么放。走样、Z-fighting、透视失真——这些实时图形里最经典的问题，根源都在这里。

## 1. 问题定义

输入：一个屏幕空间三角形 $T=(V_0, V_1, V_2)$，每个顶点带位置 $(x_i, y_i, z_i)$、$1/w_i$、以及一组属性 $\{a_i^{(k)}\}$。
输出：一批**片段**（fragment），每个片段对应一个被 $T$ 覆盖的采样点，携带插值好的深度和属性。

看似简单，但要做到又快、又准、又不闪，需要几个精心设计的部件：一个高效的覆盖测试、一套无误差的属性插值、一种处理边界像素的规则。

## 2. 历史：扫描线算法

早期光栅器（80s–90s，SGI 图形工作站、软件光栅化如 Quake 引擎）用**扫描线算法**：

1. 把三角形三个顶点按 y 排序
2. 从上顶点开始，沿两条边同时下扫，每行算出左右两个交点 $x_L, x_R$
3. 在这一行填 $[x_L, x_R]$ 之间的像素
4. 属性也按 y 增量插值（$dz/dy$、$du/dy$）；每行内按 x 增量再插一次

$$
\Delta z_x = \frac{z_R - z_L}{x_R - x_L}, \quad z(x+1) = z(x) + \Delta z_x
$$

优点：整数加法就够、缓存友好、非常适合 CPU 顺序执行。缺点：**顺序依赖强**——必须逐行逐像素，很难并行化。

现代 GPU 一秒扫几亿三角形，每个三角形只占几十像素，扫描线的启动开销都受不了，何况没法多个像素同时算。这套算法被淘汰是必然的。

## 3. 半空间算法与边缘函数

Juan Pineda 在 1988 年提出了一个漂亮的替代方案：**边缘函数**（edge function）。对三角形的一条边 $V_0 V_1$，定义：

$$
E_{01}(x, y) = (y - y_0)(x_1 - x_0) - (x - x_0)(y_1 - y_0)
$$

这是点 $(x,y)$ 到直线 $V_0 V_1$ 的**有符号"面积"**（乘 2 后）。正负号取决于点在直线的哪一侧。三角形是三条边围成的凸区域，点在三角形内的条件是：

$$
E_{01}(x,y) \ge 0 \;\wedge\; E_{12}(x,y) \ge 0 \;\wedge\; E_{20}(x,y) \ge 0
$$

（假设三角形绕序为 CCW；CW 则反号。）

边缘函数的三个性质让这套算法特别适合硬件：

1. **线性**：$E(x+1,y) = E(x,y) + (y_1-y_0)$，只需要一次加法就能得到下一像素的值
2. **可并行**：所有像素的 $E$ 值可以独立计算，没有顺序依赖
3. **能算重心坐标**：三个边缘函数的值除以三角形总面积就是重心坐标

半空间算法（每边界一个"半空间约束"）现在是所有硬件光栅器的标准做法。

## 4. 重心坐标

三角形内一点 $P$ 可写成三个顶点的加权和：

$$
P = \lambda_0 V_0 + \lambda_1 V_1 + \lambda_2 V_2, \quad \lambda_0 + \lambda_1 + \lambda_2 = 1, \quad \lambda_i \ge 0
$$

$\lambda_i$ 就是**重心坐标**。用边缘函数：

$$
\lambda_0 = \frac{E_{12}(P)}{E_{12}(V_0)}, \quad \lambda_1 = \frac{E_{20}(P)}{E_{20}(V_1)}, \quad \lambda_2 = \frac{E_{01}(P)}{E_{01}(V_2)}
$$

分母是常数（等于三角形面积的两倍）。用重心坐标插值任意属性：

$$
a(P) = \lambda_0 a_0 + \lambda_1 a_1 + \lambda_2 a_2
$$

## 5. 透视校正插值

前面那个公式对屏幕线性量是对的，但对**世界空间线性量**是错的。

看一个具体例子：一根水平放置的长棒，头部离相机近、尾部远，纹理坐标 $u$ 从头到尾从 0 变到 1。在屏幕上棒因为透视变短，等间距屏幕位置对应的**世界位置不是等间距的**——远处的世界间距被压缩了。如果直接在屏幕空间线性插值 $u$，画出来的贴图会像"贴在屏幕上"而不是"贴在物体上"，视觉上像一张纸拉伸。

正确做法：在**齐次空间**做线性插值。对每个属性 $a$，插值 $a/w$ 和 $1/w$，然后相除：

$$
a(P) = \frac{\lambda_0 \frac{a_0}{w_0} + \lambda_1 \frac{a_1}{w_1} + \lambda_2 \frac{a_2}{w_2}}{\lambda_0 \frac{1}{w_0} + \lambda_1 \frac{1}{w_1} + \lambda_2 \frac{1}{w_2}}
$$

推导：世界空间线性关系经过透视投影后，$1/w$ 保持屏幕线性，$a/w$ 也保持屏幕线性（$a$ 是世界线性的话）。所以在屏幕上用重心坐标插 $a/w$ 和 $1/w$，再相除就能还原真正的世界线性 $a$。

$w$ 从哪来？就是 VS 输出 `gl_Position.w`，未做透视除法的那个。透视校正是自动的、硬件做的，但你需要知道它在做什么——否则遇到 "深度插值精度不均匀" 这类问题时无从下手。

**深度**的处理稍微特别：由于投影矩阵设计的问题，$z_{\text{NDC}} = z/w$ 本身就是屏幕线性的，所以直接插 $z_{\text{NDC}}$ 就对。这也是为什么 $z$-buffer 里的值在近处精度高、远处精度低——它是 $1/w$ 的双曲函数而不是线性函数。

## 6. 覆盖测试与像素中心

一个像素被"覆盖"的定义是什么？主流选择：**采样点在三角形内**。

对不用 MSAA 的普通渲染，采样点就是像素中心 $(x+0.5, y+0.5)$。对 MSAA Nx，一个像素里放 N 个亚像素位置，每个位置独立测覆盖，覆盖了就生成一个片段样本。

### 6.1 Top-Left 规则

边缘上的点（$E = 0$）算不算覆盖？如果两个相邻三角形共享一条边，边上的像素两边都覆盖了就重复画（overdraw + 半透明混合错误），都不覆盖就出现"接缝亮线"。

D3D/GL 采用**top-left 规则**：只有当共享边是三角形的"上边"或"左边"时才算覆盖。定义：

- 上边：水平边、且三角形在其下方
- 左边：非水平边、且三角形在其右方

工程上通过在边缘函数上加一个小偏置（`fill rule bias`）实现——不用真去判断上下左右。

### 6.2 亚像素精度

顶点的屏幕坐标不能只是整数，否则每次相机稍微一移动，三角形边界就会"跳"一个像素，出现闪烁。硬件光栅器用固定小数点（例如 D3D 是 8 位小数、GL 至少 4 位），顶点被吸附到 $1/256$ 像素精度。这样相机连续移动时三角形边界也连续变化，只是变化步长离散。

亚像素精度是 MSAA 得以工作的前提——采样点在同一个像素内不同位置，边缘函数值会有可分辨的差异。

## 7. 三角形遍历策略

知道怎么判一个像素覆盖没，还得决定**遍历哪些像素**。三种主流：

**逐像素扫全屏**：太蠢，只在极大三角形（占满屏幕）时才不亏。

**扫描三角形包围盒**：算出三角形的 AABB，对盒内所有像素测三个边缘函数。简单，但小三角形浪费不多、大三角形也不算多——是 GPU 常用起点。

**层级 Tile 遍历**：把屏幕划成 $8\times 8$ 或 $16\times 16$ 的 tile，先测一个 tile 的四角是否全在某条边外——是的话整块跳过。层级化，粗排除后再细扫。真实 GPU 用的都是这一套，配合 Hi-Z 剔除（tile 级深度快速比较）。

```
    +---+---+---+---+
    | . | X | X | . |   X = tile 与三角形相交，展开细扫
    +---+---+---+---+   . = tile 完全在外，跳过
    | X | X | X | X |
    +---+---+---+---+
```

## 8. 属性插值实现

硬件光栅器有专门的**属性插值器**（attribute interpolator），每种属性一个通道，输入是三个顶点属性值加上当前像素的重心坐标，输出是插值结果。透视校正在这里做。

一次像素着色的完整输入准备：

1. 边缘函数计算 → 重心 $\lambda_0, \lambda_1, \lambda_2$
2. 对每个 varying $a$：读 $a_0/w_0, a_1/w_1, a_2/w_2$，加权得 $a/w$；同时插 $1/w$；相除得 $a$
3. 特殊处理深度 $z_{\text{NDC}}$：不需要透视校正
4. 打包成 FS 输入下发

varying 数量越多，插值器就越忙，硬件通常有 32 个 vec4 varying 上限。写 shader 时 varying 是稀缺资源。

## 9. 2×2 Quad 与屏幕空间导数

FS 里能用 `ddx(uv)`、`ddy(uv)` 得到相邻像素的差分。这个功能不是白来的——GPU 强制把片段按 **2×2 quad** 打包调度，同一个 quad 的四个片段并行执行同一条指令，导数就是 quad 内的相邻差值。

为什么要 ddx/ddy？**Mipmap 选级**需要它——采样一张贴图时，纹理坐标在屏幕上的变化率越大，就该用越粗的 mip 层：

$$
\lambda = \log_2\left(\max\left(\sqrt{(\partial u/\partial x)^2+(\partial v/\partial x)^2},\, \sqrt{(\partial u/\partial y)^2+(\partial v/\partial y)^2}\right)\right)
$$

Quad 打包有个副作用：**三角形边缘会生成"废片段"**。一个三角形只覆盖 quad 的一个像素时，另外三个像素也会被生成（但 FS 结果被丢弃），只为给这一个像素提供导数。这就是**helper invocation**。小三角形（$\le 8$ 像素）的 quad 利用率极低，是现代高多边形渲染的性能杀手——Nanite 用软件光栅化的部分原因就是硬件光栅器处理这种"微三角形"太浪费。

## 10. Early-Z 与 Hi-Z

严格按管线顺序，深度测试在 FS 之后。但如果一个片段最终会被深度测试丢弃，那 FS 白跑了。**Early-Z**：在 FS 之前先做深度测试，直接丢弃看不见的片段。

Early-Z 的前提：**FS 不能修改深度**。如果 shader 里写 `gl_FragDepth = ...`（少见但合法），硬件必须禁用 Early-Z，因为不算 FS 就不知道真实深度。同理 `discard` 语句：discard 会决定片段是否写入，如果 discard 在 FS 里，硬件某些实现下也会关 Early-Z。

**Hi-Z**（分层 Z）是 tile 级的深度快速拒绝。GPU 维护一份低分辨率的**最大深度**记录——每个 $8\times 8$ tile 存该区域里最远的深度。光栅化一个三角形前，先看它某个 tile 的最小深度 $z_{\min}$ 是不是大于 Hi-Z 里的最大值——是的话整个 tile 的片段全部剔除，连 quad 打包都省了。

Hi-Z 对**近处物体优先绘制**特别有效——如果先画近景填了 Z-buffer，远景 tile 大部分被 Hi-Z 直接踢掉。所以工业界的一般策略：不透明物体从前到后画（front-to-back），最大化 Hi-Z 收益。

## 11. 保守光栅化与其他扩展

**保守光栅化**（Conservative Rasterization，DX12/Vulkan 扩展）：只要三角形与像素有**任何面积重叠**就算覆盖。用途：体素化、图形碰撞、遮挡查询。跟默认规则（采样点判定）不同，标准做法覆盖不了的边角像素也会算进去。

**可变着色率**（Variable Rate Shading，VRS）：每 $2\times 2$ 或 $4\times 4$ 像素共用一次 FS 调用。视觉上主要区域全率、周边低率，省 30% 以上 FS 成本。RTX 20 系起硬件支持。

## 12. 与其他阶段的接口

光栅化的输入来自 [顶点处理与图元装配](./顶点处理与图元装配.mdx)——屏幕空间三角形加每顶点的 $1/w$ 和属性。

输出是**片段流**：位置 $(x, y)$、插值属性、深度 $z_{\text{NDC}}$，进入 [片段处理与输出合并](./片段处理与输出合并.mdx) 做着色和帧缓冲写入。

MSAA 的每采样点覆盖信息也在这里生成，会影响下游的深度/模板测试粒度。详细的走样成因和补救见 [抗锯齿技术](../后期处理与视觉特效/抗锯齿技术.mdx)。

## 14. 光栅化的局限

光栅化算得快、专用硬件加速、对静态场景近乎免费。但它有几个先天缺陷：

- **只能画三角形**：曲面必须先细分。真曲面渲染（如 Bezier patch）要么细分、要么走光线追踪
- **不擅长处理复杂全局效应**：反射、折射、软阴影都要各种 trick 或者多趟渲染
- **微三角形效率崩塌**：屏幕上占 1–4 像素的三角形浪费 quad 打包和 setup 成本

前两条催生了光线追踪回归。第三条催生了 Nanite 这种软件光栅化 + 层次化 LOD 的现代方案。但对 90% 的实时图形，硬件光栅化仍然是最快最省的路径——理解它的每一步在做什么，才能理解为什么某些渲染现象是那样、某些性能问题会那样发生。
