> **L5 工程化层**：可视化、调试、性能、测试比再多几种节点类型更重要。甜点区到此收束。

## 大纲

### 1. 为什么工程化决定能不能用
- 树上逻辑一复杂，纯代码拼树会失读性
- 实机问题多是：不知道当前跑到哪、为何被打断、黑板当时是什么
- 团队协作需要：可审阅的资产、可回放的失败、可回归的用例

### 2. 可视化编辑器要什么
- 拖拽组合节点、参数面板、子树复用
- 黑板键提示 / 类型检查
- 与版本管理友好的文本序列化（JSON/XML/YAML）
- 热重载：改树不重启整个机器人栈（或至少不重启仿真）

### 3. 运行时调试
- 高亮当前 Running 路径
- 节点状态历史、进入/退出时间戳
- 黑板快照与关键键监听
- 日志：结构化（tree_id, node_id, status, bb_diff）

### 4. 性能关注点
- 每 tick 遍历成本、条件计算成本
- 避免在 Condition 里做重感知；感知异步写入黑板
- 内存：节点对象分配、字符串键、GC（若托管语言）
- 子树休眠：未激活分支少做无用功

### 5. 测试策略
| 层级 | 测什么 |
| :--- | :--- |
| 叶子单测 | Action/Condition 在假世界下的返回序列 |
| 子树测 | 给定黑板序列，期望状态轨迹 |
| 场景测 | 仿真里任务成功率、中断是否生效 |
| 回放 | 录制 tick 输入，离线复现失败 |

### 6. 与 ROS / 中间件集成时的工程点
- Action Client 取消、超时、抢占
- 树与 launch/参数的配置边界
- 仿真（Gazebo/Isaac）与实机的同一套树，差异进黑板或叶子适配层

### 7. 落地检查清单
- [ ] 能看见当前 Running 节点
- [ ] 能 dump 黑板
- [ ] Action 实现了 Halt
- [ ] 关键子树有单元/轨迹测试
- [ ] 树资源可 diff、可 Code Review
