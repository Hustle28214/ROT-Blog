> **L4 数据与反应式层**：Sequence/Selector 只是表面；中断和黑板才是难关。

## 大纲

### 1. Blackboard 是什么
- 树上的**数据总线**：节点之间不直接耦合，读写键值
- 典型内容：目标位姿、电量、检测到的物体 ID、导航状态、任务参数
- 对比：全局单例乱写 vs 有作用域的黑板

### 2. 作用域与生命周期
| 范围 | 用途 | 风险 |
| :--- | :--- | :--- |
| 全局 | 机器人本体状态、模式 | 隐式依赖、难测 |
| 树级 | 一次任务的上下文 | 任务切换时残留 |
| 子树 / 节点局部 | 临时变量 | 作用域不清导致读空 |

要点：谁写、谁读、何时清、失败后是否保留。

### 3. 事件驱动 vs 轮询 Tick
- 固定频率 tick：实现简单，可能空转
- 事件驱动：传感器/话题更新才 tick，更省、更反应
- 机器人常见：控制高频；BT 中频或事件触发混合

### 4. 中断（Abort）与 Observer
- 低优先级分支 Running 时，高优先级条件变真 → 需要打断
- Observer Aborts（UE 等实现中的概念）：监视条件变化，触发下层 abort
- 需要定义：Abort 时 Action 如何取消（停导航、松爪、回零）

### 5. 反应式设计模式
- “监视器 + 执行器”：Parallel 里一个条件失败则整支失败
- “优先打断”：电量危急、急停、人靠近
- “条件门禁”：Decorator 包一层前置条件，变化即重置子树

### 6. 取消语义（机器人特有）
- 叶子 Action 必须可取消：`onStart / onRunning / onHalt`
- Halt 后资源释放：控制器目标、夹爪命令、ROS action cancel
- 取消不干净 = 实机最常见事故源之一

### 7. 踩坑清单
- 黑板键名散落、无类型、无文档
- 中断后子节点未 halt，动作继续跑
- 每 tick 重读条件导致抖动（需要迟滞 / 去抖）
- 多树共享全局黑板互相覆盖
