# 颜色与视觉：色彩空间与人眼感知

图形学里最容易被忽视的领域,大概就是颜色。绝大多数教程直接写 `vec3 color = ...`,好像 R、G、B 三个数就是颜色本身。但**颜色是人眼的心理物理反应,不是物理量**——同一个光谱在不同人眼里、不同环境里、不同显示器上都可能是不同的"颜色"。搞不清 RGB 和光强的关系,渲染出来的图像就会有一堆诡异问题:HDR 场景过曝、法线贴图颜色算错、SSAO 输出过暗、动态范围压缩不自然。

这一篇不进颜色科学的深水区,只讲**图形学工程里必须知道的部分**:光是什么、人眼怎么看、色彩空间为什么这么多、伽马校正到底在做什么、色调映射为什么必须做。

## 1. 光的物理:一切从光谱开始

可见光是波长 380nm(紫)到 780nm(红)的电磁波。**光的物理描述是光谱**——一个从波长到能量密度的函数 $S(\lambda)$。

阳光的光谱大致像黑体辐射曲线(色温 5800K),白炽灯偏红(约 2700K),日光灯有几条离散的荧光峰,LED 蓝色主峰加荧光粉的黄色宽峰。**不同光谱可以在人眼里产生相同的颜色感觉**——这叫"同色异谱"(metamerism),是颜色科学的基础事实。

$$
\text{颜色感觉} = \text{光谱} \star \text{视网膜响应}
$$

问题的核心就在星号后面那一项。

## 2. 人眼:三种锥细胞与视杆细胞

视网膜有两类感光细胞:

- **锥细胞**(cone):三种,分别对**长波(L,峰值约 564nm,红)**、**中波(M,约 534nm,绿)**、**短波(S,约 420nm,蓝)** 敏感。负责**明视觉**和**彩色感知**,集中在中央凹。
- **视杆细胞**(rod):一种,峰值约 498nm,极高灵敏度,负责暗视觉和运动感知,分布在周边,不区分颜色。

**三色视觉**(trichromacy):任意可见光谱通过三种锥细胞的响应函数积分得到三个数 $(L,M,S)$。眼睛把无穷维的光谱压缩成三维颜色——这是所有 RGB 颜色系统的生理学基础。

```
响应
  │        L (红) ~564
  │       ╱\
  │      ╱  \
  │  M(绿)   \
  │ ╱\        \
  │╱  \        \
  │S   \        \
  │(蓝) \        \
  │──────────────────> 波长
   400  500  600  700
```

三条曲线的峰值告诉我们"红绿蓝"是感光峰位置,但这三种细胞的响应曲线严重**重叠**——L 和 M 峰值只差 30nm——所以"看到红色"不是 L 单独响应,而是 L/M 比值大。色盲(色觉异常)常见的是 L 或 M 缺失,导致这个比值失效,红绿混淆。

**视觉的非线性**:眼睛对亮度的响应是**对数**的(Weber-Fechner 定律近似)。0.1 到 0.2 的亮度差异远比 0.9 到 1.0 明显。这个非线性是伽马编码存在的根本理由,见第 5 节。

## 3. CIE XYZ:标准观察者的参考系

1931 年 CIE(国际照明委员会)找了一批"标准观察者",用色匹配实验测出三条**色匹配函数** $\bar{x}(\lambda),\bar{y}(\lambda),\bar{z}(\lambda)$。任意光谱 $S(\lambda)$ 对应的 XYZ 是:

$$
X=\int S(\lambda)\bar{x}(\lambda)d\lambda, \quad Y=\int S(\lambda)\bar{y}(\lambda)d\lambda, \quad Z=\int S(\lambda)\bar{z}(\lambda)d\lambda
$$

$Y$ 特意设计成对应人眼的**亮度感知**(luminance)。$X,Z$ 承担色度信息。

XYZ 是**设备无关**的、涵盖所有人眼可见颜色的参考坐标系。所有其他色彩空间都能通过矩阵变换与它互转。它是颜色科学的"世界坐标系",相当于图形学里的"世界空间"。

### 3.1 CIE xy 色度图

把 XYZ 归一化 $x=X/(X+Y+Z),y=Y/(X+Y+Z)$,得到二维色度图——就是那个熟悉的**马蹄形**。

- 马蹄边界是光谱色(单色光)
- 马蹄底部的直线是紫色线(非光谱色,红蓝混合)
- 中心 $(0.33,0.33)$ 附近是白色
- 任意点是内部所有它顶点的凸组合

**色域**(gamut)就是设备能显示的颜色在这张图上覆盖的三角形。三角形越大,能显示的颜色越多。sRGB 覆盖马蹄一小部分,DCI-P3 覆盖更多,Rec.2020 更大,但都远远不能覆盖整个马蹄。

## 4. 主流色彩空间

| 空间 | 用途 | 特点 |
|---|---|---|
| CIE XYZ | 参考、颜色科学 | 全人眼色域,设备无关 |
| CIE Lab | 色差度量、修图 | 感知均匀,$L$ 是亮度 |
| sRGB | 网页、消费显示器 | 覆盖窄,带伽马 |
| Adobe RGB | 印刷、专业修图 | 比 sRGB 广,尤其绿色 |
| DCI-P3 | 电影、高端手机 | 电影行业标准 |
| Rec.709 | HDTV | 和 sRGB 色域相同 |
| Rec.2020 | 4K/8K HDR 电视 | 色域接近 XYZ 边界 |
| ACES | 电影工业标准 | 覆盖所有物理可见 |

### 4.1 RGB 与 XYZ 的转换

sRGB → XYZ:

$$
\begin{bmatrix}X\\Y\\Z\end{bmatrix} = \begin{bmatrix}0.4124&0.3576&0.1805\\0.2126&0.7152&0.0722\\0.0193&0.1192&0.9505\end{bmatrix}\begin{bmatrix}R\\G\\B\end{bmatrix}
$$

第二行系数 $(0.2126, 0.7152, 0.0722)$——这就是把 RGB 转成亮度的著名系数,用于灰度化。绿色权重最大,因为人眼对绿色最敏感。

从 RGB 换到其他 RGB(如 sRGB 到 Rec.2020)需要**先转到 XYZ 再转回去**——两次矩阵乘。近年 GPU 硬件的 wide color 支持在 shader 里直接做这一步。

### 4.2 HSV 与 HSL:艺术家的坐标

HSV(色相 Hue、饱和度 Saturation、明度 Value)和 HSL(色相、饱和度、亮度)是 **RGB 的直接重参数化**,而不是真正独立的色彩空间。转换是纯几何的:把 RGB 立方体投影到六边形色轮。

用途:调色板、拾色器、图像调色。缺点是"感知不均匀"——HSV 里等距的两个颜色对眼睛的差异感不相等。要感知均匀应该用 CIE Lab 或 OKLab。

### 4.3 Lab 与 OKLab

CIE Lab(1976)设计为**感知均匀空间**:两个颜色在 Lab 空间里的欧氏距离约等于人眼感受的差异。$L$ 是亮度、$a$ 是绿红轴、$b$ 是蓝黄轴。计算色差 $\Delta E$、K-Means 聚类做调色板,都在 Lab 里做。

OKLab(2020) 修正了 Lab 的一些缺陷(高饱和度处的非均匀),是现代软件(Figma、CSS Color 4)的推荐选择。

## 5. 伽马:图形学最诡异的话题

CRT 显示器物理上是**非线性**的:输入电压 $V$ 对应输出光强 $I=V^\gamma$,$\gamma\approx 2.2$。图像传输方案顺应了这个:摄像机的编码曲线是 $V=I^{1/\gamma}$,显示器的解码曲线是 $I=V^\gamma$,两者串联得到线性。CRT 已经死了几十年,但这套编码规则被 sRGB 标准继承下来,活到了今天。

**为什么 CRT 死了还保留伽马**?两个原因:

1. **兼容性**:全世界几十亿张图像都是这么编码的
2. **感知优化**:人眼对暗部敏感,把 8-bit 编码空间的大部分分配给暗部才不会看到 banding。伽马编码正好实现了这个——数学上恰好近似了 Weber-Fechner 定律。

### 5.1 伽马正确的着色

图形学里一切光学计算(光照、混合、SSAO、抗锯齿)都应该在**线性空间**里做,而不是 sRGB。原因是"光是可加的",而 sRGB 里的加法是错的:$0.5+0.5\neq 1$,但相同两束光叠加物理上就是两倍强度。

正确流水线:

```
纹理(sRGB) --解码--> 线性 --渲染--> 线性 HDR --色调映射--> LDR --编码--> sRGB(显示)
```

- **纹理解码**:采样 sRGB 纹理时硬件自动 $c^{2.2}$(GL_SRGB 格式或 `GL_FRAMEBUFFER_SRGB`)
- **所有光照/混合/后处理**:线性空间
- **最后写回 framebuffer**:再编码回 sRGB($c^{1/2.2}$)

**法线贴图不能当 sRGB 处理**——它存的是方向,不是颜色。用 `GL_RGB` 而不是 `GL_SRGB`。这个坑无数人踩过——法线贴图颜色偏亮或偏暗,光照全错。

### 5.2 sRGB 传输函数的精确形式

sRGB 不是纯 $\gamma=2.2$,而是分段函数:

$$
V = \begin{cases} 12.92\,I & I\leq 0.0031308 \\ 1.055\,I^{1/2.4}-0.055 & I>0.0031308 \end{cases}
$$

低亮度用线性段避免除零和精度损失。但很多着色器为了性能用近似 $V=I^{1/2.2}$——大多数场景可以接受。

## 6. HDR 与色调映射

**HDR**(High Dynamic Range)指亮度范围远超 sRGB(0-1)的图像。真实世界的亮度跨越 10 到 14 个数量级(星光到阳光),显示器只有 3 个左右(300 nit HDR400 屏幕、10000 nit HDR10000 概念屏)。**色调映射**(tone mapping)负责把 HDR 压缩到显示器能显示的动态范围。

朴素做法:除以最大值。问题是场景里一个太阳会把所有其他物体压成黑色。

### 6.1 Reinhard 色调映射

$$
V_{\text{disp}} = \frac{V_{\text{hdr}}}{1+V_{\text{hdr}}}
$$

低亮度近似线性(保留细节),高亮度饱和到 1(不过曝)。简单、鲁棒,论文里默认基线。

改进版是"白点归一化"的 Reinhard:

$$
V_{\text{disp}} = \frac{V_{\text{hdr}}(1+V_{\text{hdr}}/L_{\text{white}}^2)}{1+V_{\text{hdr}}}
$$

$L_{\text{white}}$ 是"应映射到白"的 HDR 亮度阈值。

### 6.2 ACES 色调映射

电影工业标准 ACES 的 filmic tone mapping,提供更"电影感"的曲线——暗部有 toe(脚趾)、亮部有 shoulder(肩膀),模拟胶片的响应。近似公式:

$$
V_{\text{out}} = \frac{V(2.51V+0.03)}{V(2.43V+0.59)+0.14}
$$

Unreal、Unity 都默认用 ACES 或其变种。UE5 的 sRGB 输出走的是完整 ACES 变换,几十行 shader,但结果显著优于 Reinhard。

### 6.3 曝光控制

在色调映射前需要一个**曝光**(exposure)乘数:

$$
V_{\text{exposed}} = 2^{EV}\cdot V_{\text{hdr}}
$$

$EV$ 是曝光值。自动曝光(auto-exposure)根据画面平均亮度动态调整,模拟人眼从室内走到户外的适应过程。实现方式是采样上一帧的直方图或平均值(EV100),平滑地拉向目标。这是 AAA 游戏"从黑屋子出门先炸一下白"的成因。

### 6.4 HDR 显示

现代 HDR 显示(HDR10、Dolby Vision)不做色调映射,而是把 10-12 bit 的高动态范围数据直接送屏——显示器有 1000+ nits 峰值亮度硬件支持。渲染管线里的色调映射就变成"HDR 输出到 HDR 显示的调色"而不是"压缩到 8 bit sRGB"。这需要色彩管理(color management)、EOTF(电光传递函数)等一整套新流程,PQ 或 HLG 传输函数取代 sRGB。

## 7. 白平衡与色适应

眼睛会自动**适应**光源的颜色——白纸在白炽灯下、日光下、荧光灯下你都看它是白的,但相机拍出来会偏黄/中性/偏绿。这个自动适应叫**色适应**(chromatic adaptation)。

图形学里的对应操作叫**白平衡**——把某个"应该是白"的物体色度移到 D65(标准日光白)。矩阵变换 Bradford transform 或 CAT02 是常用做法。

游戏里的"环境色偏"(黄昏偏橙、深水偏蓝)可以理解为反向操作——故意不做白平衡,让画面染上光源的颜色。

## 8. 抗锯齿和线性空间

**抗锯齿在线性空间做,还是 sRGB 空间做**?——正确答案是线性。原因:AA 本质是采样重建,把光强平均起来。sRGB 空间里 $(0+1)/2=0.5$,解码后是 $0.5^{2.2}\approx 0.22$,而线性下 $(0+1)/2=0.5$,再编码是 $0.5^{1/2.2}\approx 0.73$。前者比正确亮度暗一倍。

现代 GPU 的 `GL_FRAMEBUFFER_SRGB` 或 `SRGB8_ALPHA8` framebuffer 在混合前自动解码,混合后自动编码——硬件帮你做对。手动实现 blend 时要注意。

## 9. 颜色的分色不是数学的分色

美术里说的"互补色"(红-青、黄-蓝、绿-品红)是**颜色感知的互补**,即 CIE xy 色度图上过白点的连线两端。这和 RGB 的"数值取反"$(1-R,1-G,1-B)$ 不同。前者在 Lab 或 XYZ 里做,后者在 sRGB 里做,视觉效果差异明显。

配色工具(Adobe Color、Coolors)背后都是 HSL 或 LCh 空间里的几何操作——120° 相位差得三色对比、30° 相位差得类似色。UI 设计里熟悉这套规则的价值远高于死记颜色代码。

## 10. 图形学工程师的颜色清单

一份实用清单,做渲染时逐条检查:

- [ ] 所有纹理源(diffuse、albedo)标记为 sRGB,硬件自动解码
- [ ] 法线贴图、粗糙度贴图、金属度贴图、AO 贴图标记为**线性**,不要 sRGB 解码
- [ ] 光照、后处理在**线性 HDR** framebuffer(RGBA16F 或更高)里做
- [ ] 有色调映射,不是简单 clamp
- [ ] 有伽马编码写回 sRGB(或走 HDR 直显链路)
- [ ] Blend 在线性空间做(硬件 SRGB framebuffer 会自动)
- [ ] UI/HUD 元素明确处于哪个空间,避免文字染色错误
- [ ] 颜色调色板设计时避免相邻色饱和度差太多,防止 banding
