## 共识机制

设想我们和几个朋友一起玩桌游,想要一个共同的账本记录每个人的分数。如果只有一个人负责记账,大家就得相信这个人不会作弊;如果每个人都自己记一份,那么当有人漏记或者故意改数字时,我们如何决定"到底谁的账本才算数"?这就是分布式记账要面对的核心问题。区块链的解答方式,就是我们这一节要讨论的共识机制。

在开始具体的算法之前,我们先记住两条来自分布式系统的老结论。第一条是 CAP 定理:一致性、可用性、分区容错这三件事,一个分布式系统最多能同时满足两件。区块链跑在公开互联网上,网络分区是家常便饭,所以 P 是硬约束,余下的一致性和可用性只能挑一个偏向。第二条是 FLP 不可能性:在完全异步的网络里,只要有一个节点可能挂,就不存在能"确定性"达成共识的算法。这意味着现实中的共识算法,要么加一点同步假设,要么引入随机性绕开 FLP。

把这两条放在心里,后面看到的每种共识都会显得没那么神奇——它们都在同一个约束下做取舍。

### 工作量证明

我们从最早、也是最容易想清楚的方案开始。比特币的做法是,每一轮出块之前,大家一起解一道数学题:找一个数 $nonce$,使得区块内容加上这个数以后的哈希值前面有若干个 0。因为哈希不可预测,唯一办法就是不停试。谁先试出来,谁就有权把新区块广播出去,并领取一份区块奖励。

这个过程用几行代码就能演示。

```python
import hashlib

def mine(data, difficulty):
    target = "0" * difficulty
    nonce = 0
    while True:
        h = hashlib.sha256(f"{data}{nonce}".encode()).hexdigest()
        if h.startswith(target):
            return nonce, h
        nonce += 1

print(mine("block#1", difficulty=5))
```

难度每加 1,期望尝试次数就翻 16 倍。所以"算力"这个词在物理上并不虚,它对应着实实在在的 CPU 循环和电费。

那么问题来了:为什么这套机制可以防止有人伪造账本?想象一个作恶者要修改第 100 个区块里的一笔转账。他改完之后这一块的哈希就变了,而第 101 块里存了第 100 块的哈希,对不上;所以第 101 块也要重挖,而第 101 块的哈希一变,又会波及第 102 块。以此类推,直到追上当前的最新区块。要重新算这一段,他需要的算力超过全网诚实节点在同一时间的算力总和。这就是我们常说的 51% 攻击:只要作恶者算力不到一半,他永远追不上主链。

工作量证明的漂亮之处在于概念简单,不需要预设任何身份,谁想加入都可以。它的代价也很直白:全网节点在做的绝大多数工作是"为了防作弊而算哈希",几乎没有其他产出。比特币全网算力换算成电力,大约相当于一个中等国家的耗电量。此外,当矿工用 ASIC 专用芯片替代通用 CPU 之后,算力实际上又集中到了少数矿池手里,与"人人可挖"的初衷有些偏离。

### 权益证明

如果算力上限只是"谁能烧更多电",那么烧电这件事本身其实没有创造价值。以太坊在 2022 年做的"合并"就是把这套挖矿彻底换成了权益证明:出块的权利不再靠算力,而是靠质押。你把币锁进合约,变成一个验证者,以后按质押量的比例被随机抽中出块和投票;如果作恶(比如同一时刻给两条冲突的链都签名),这份质押会被"砍资"扣掉。

从"算力有成本"到"作恶有成本",本质上是一件事的两种形态:PoW 里成本花在事前(烧电挖矿),PoS 里成本花在事后(可能被 slash 的质押)。两者都在回答"作恶要付出什么"这个问题,只是形式换了。

以太坊主网现在跑的算法叫 Gasper,由两部分组合而成。一部分叫 LMD GHOST,负责在每一个 12 秒的 slot 里选出块提议者,追求高活性;另一部分叫 Casper FFG,每 32 个 slot(称为一个 epoch)做一次 checkpoint 投票,当超过三分之二的质押投同一个 checkpoint,这个点就被 finalize,理论上永不回滚。要回滚就得让三分之一以上的验证者被砍资,代价是几十上百亿美元的质押灰飞烟灭。

PoS 也有自己的坑,几个常被讨论的话题:

一个是"无成本作恶"。既然在分叉的两条链上同时投票几乎不花额外的算力,为什么验证者不都这么干?答案是 slashing:同一 slot 里给两条链都签名会被自动检测出来并罚没质押,少则罚 1 ETH,多则 32 ETH 全部归零。作恶变得有成本,均衡就回到了诚实一边。

另一个是长程攻击。一个已经退出的验证者,理论上可以用当年的私钥在很久以前的某个 checkpoint 上拉一条平行历史。因为他早已提取了质押,slash 不到他。解决办法是弱主观性:新节点第一次加入网络时,不能从创世块开始纯靠算法判断哪条链是主链,而是要从"社会共识"(比如 GitHub 上的官方 checkpoint)拿到一个近期的信任点。这是 PoS 对 PoW 的一处让步——PoW 的新节点理论上真的可以只带着创世块加入网络。

### 拜占庭容错

上面两种共识,不管是 PoW 还是 LMD GHOST,都是"概率最终性"的:一笔交易上链后,并不是立刻定死,而是随着后续区块增多,被回滚的概率指数衰减。这对用户不够友好,尤其是想做支付或者跨链的场景。有没有一种算法,能让交易一上链就永远不回滚?这就是拜占庭容错(BFT)家族在做的事。

BFT 的祖师爷是 1999 年 Castro 和 Liskov 提出的 PBFT。想象我们有 3f+1 个记账节点,其中最多允许 f 个作恶。每一轮出块要走三个阶段:预准备、准备、提交。只要每个阶段都收到至少 2f+1 个不同节点的一致签名,一轮之内就能敲定一个区块,而且这个区块永远不会被回滚。

现代的 BFT 算法有一箩筐,但都长得像 PBFT 的变体。Tendermint(Cosmos 系用的)保持了 PBFT 的三阶段结构;HotStuff(Aptos、Diem 用的)把多轮广播压成流水线,主席轮换的成本极低;Sui 和 Aleo 用的 Narwhal + Bullshark 把数据传播和共识拆开,吞吐能到几万 TPS。

BFT 的代价是通信开销。每一轮所有节点两两广播,复杂度是 $O(n^2)$ 甚至 $O(n^3)$,所以验证者数量必须限制在几十到几百这个量级——上不了以太坊那种几十万个验证者的规模。另一个代价是,BFT 在网络分区时会直接停摆,等分区结束再恢复;而 PoW 分区之后两边会各自继续挖矿,分区结束时选最长链合并。前者在 CAP 里偏 CP,后者偏 AP。

### 三者放一起看

我们把三种共识的关键特性汇总一下,方便对比。

| 维度 | 工作量证明 | 权益证明 | 拜占庭容错 |
|---|---|---|---|
| 出块者选择 | 谁先算出谁出 | 按质押加权抽签 | 主席轮换 |
| 最终性 | 概率(越深越安全) | 概率 + 定期 finalize | 一块一 finalize |
| 验证者规模 | 无限制 | 上万级 | 上百级 |
| 网络分区时 | 两边继续挖,合并 | 类似 PoW | 停摆等待 |
| 单位时间能耗 | 极高 | 极低 | 极低 |
| 代表项目 | Bitcoin | Ethereum(合并后) | Cosmos、Sui、Aptos |

值得留意的是,这三种共识并不是"新的一定比老的好"。比特币仍然运行 PoW,不是因为设计者没听说过 PoS,而是这个系统的目标是抗审查和长期稳定,PoW 的物理属性提供了别的方案很难替代的抗攻击强度。选共识就像选算法,不看流行度,看目标。

### 一些真实事件

理论讲完之后,我们看几个实际发生过的故障。它们比论文更有说服力,也更能帮我们建立直觉。

2013 年比特币曾因为 0.8 版本的一个客户端 bug,出现过 24 个区块的临时分叉,交易所紧急暂停充值。当时的教训是"客户端多样性"很重要——如果全网只有一种实现,一个 bug 就是全网停摆。

以太坊经典(ETC)在 2019、2020、2021 年先后被 51% 攻击了几次,每次都伴随着几百万美元的双花。小币种的算力便宜到可以从租算力网站按小时买,所以 51% 攻击对它们并不遥远。反过来看,比特币的算力已经贵到国家级预算才能撼动,这是"越大越安全"的另一种表现。

2022 年 Solana 因为交易洪水导致共识层活性丧失,全网停机若干小时。这是把吞吐量拉得太满带来的稳健性代价。

2023 年以太坊也出过一次险情:两个主流客户端(Prysm 和 Teku)几乎同时出现 bug,差点触发 finalize 停摆。再一次证明客户端多样性不是可选项而是必选项。

### 小结

这一节我们讨论了三类主流共识:PoW 靠算力成本、PoS 靠质押成本、BFT 靠多数投票。它们都在解决同一个问题——如何让一群互不信任的节点对账本达成一致——但因为选择的取舍不同,呈现出的性质也不同。工程上没有银弹,选哪种共识,取决于你想优化什么、能牺牲什么。

### 练习

1. 假设某小币种全网算力等价于每小时 1000 美元的租金,一个交易所要求 6 个确认才放币。如果一个作恶者能维持 51% 的算力 1 小时,他大概能做到什么规模的双花?这提示我们"要求几个确认"这个数字背后的含义是什么?
2. 在权益证明中,如果一个验证者掌握了 40% 的质押,他能做什么、不能做什么?对比一下在 PoW 里掌握 40% 算力的情况。
3. PBFT 的通信复杂度是 $O(n^2)$。如果 n 从 100 增加到 10000,通信量增加多少倍?这从工程角度解释了为什么 BFT 系的公链验证者数量不能太多。
4. 试着为自己设计一个玩具共识:三个人玩桌游,你希望没有一个人能篡改分数记录。你可以用 PoW 或 PoS 的思路,也可以自己想。写下你的方案,并思考它在什么情况下会失效。
